# 陪伴同行：拾物收集設計草案

> 狀態：**第 1 步最小版已實作、未 commit**（2026-11-24，見 §15）；其餘仍是草案。
> 前置：`docs/walk-together-design.md`（計步陪伴，分支 `feat/walk-together`，尚未合併）。本文件只加道具，不改計步的讀取方式。
> 範圍：DeST 手機獨立版（Android）。桌面、遙控模式不做。
> 標記：✅ owner 明確說過／💡 依推薦，owner 尚未逐項確認／❓ 未決（集中在 §12）。
> 所有數字都是**暫定值**，實測後再調。

---

## 1. 一句話

走路會撿到未知的小東西，點開才知道是什麼；由角色講它的故事，再聊它、擲骰看它惹出什麼事、合成新的東西。

核心樂趣是**收集與不知道會撿到什麼**（✅）。程式決定「撿到哪一類、多稀有」，LLM 只寫「它叫什麼、有什麼故事」（💡）。

### 不可違反的前提

- 不懲罰、不催促、不責備，沒有連續天數（沿用 walk 設計 §2）。
- 背景與小工具**不呼叫 LLM、不啟動 WebView**。
- prompt **不含縣市名**；本功能**不取用定位**。
- 不使用任何既有遊戲的名稱、角色、美術或外觀。

## 2. 道具的一生

```text
走路 → 開 App 記帳時撿到（程式抽好，尚未揭曉）
     → 點開：LLM 生成 → 自動收進道具欄（✅ 2026-11-24，沒有保留步驟）
     → 道具欄：聊聊這個、用用看（共 3 次）、合成
     → 用完 3 次，或成為合成材料 → 移到圖鑑「紀錄」
```

| 狀態 | 可以做什麼 |
|---|---|
| 未揭曉 | 點開、直接丟（不花 LLM）。不過期 |
| 保留中 | 聊聊這個、用用看、合成、丟掉 |
| 紀錄（用完／成為材料） | 看、聊聊這個。不能再用或合成 |
| 已丟掉 | 故事刪除；圖鑑那格仍亮「曾發現」 |

- 點開才生成、揭曉後自動收好、之後可丟掉：✅
- 道具欄不設上限，不逼使用者丟東西：💡
- **不能重新生成同一件**；只有生成失敗才能重試：💡
- 丟掉道具不會刪除已經聊過的對話：💡

## 3. 撿到

### 3.1 觸發（💡）

- 每累積隨機 **1,200～2,500 步**撿到一件，撿到後再抽下一個門檻。一天 8,000 步約 4 件。
- 畫面不顯示還差幾步，避免期待變成倒數。
- **沒有同行角色時不撿**，與 walk 記帳規則一致。
- 發現者＝記帳當下同行角色中隨機一位，存下名字快照；角色之後刪除，道具仍保留名字。
- 首次啟用只建立起點，不補發。

### 3.2 分類

八類，統一兩字。✅ 2026-11-24 改成口語名稱（原為微光、餘音、墨跡、匣藏、自然、遺落、機巧、未名），id 不變。

| id | 顯示名稱 | 畫面說明，也是給 LLM 的條件 | 圖示 |
|---|---|---|---|
| `glow` | 發光 | 會發光的東西 | 光點 |
| `sound` | 聲響 | 會響、帶著聲音的東西 | 鈴 |
| `ink` | 字圖 | 寫了字或畫了圖的東西 | 紙 |
| `vessel` | 容器 | 裡面裝著什麼的東西 | 瓶 |
| `nature` | 自然 | 石、貝、葉、羽等自然物 | 葉 |
| `lost` | 舊物 | 有歲月痕跡的老東西 | 鑰匙 |
| `gear` | 零件 | 零件與小機關 | 齒輪 |
| `unknown` | 謎物 | 說不出是什麼的東西 | 問號方塊 |

分類刻意抽象、不綁世界觀。生成時**給 LLM 說明欄，不給兩字名稱**。

**通則**：道具必須是**可以長久保存的物品**；不寫會腐壞的食物、活物、屍體。

### 3.3 稀有度（💡）

| id | 顯示名稱 | 機率 |
|---|---|---|
| `common` | 尋常 | 70% |
| `uncommon` | 罕見 | 25% |
| `rare` | 奇珍 | 5% |

- 連續 25 件沒有奇珍，下一件必為奇珍。
- 只影響驚喜與故事分量，不影響使用次數或任何數值。
- 稀有度是**品項固有的**：先抽稀有度，再從該級 8 類的品項平均抽一種（§3.5）。

### 3.4 帶著走（💡，後面的步驟）

同時只能帶一件保留中的道具，讓同類機率約從 12.5% 變 25%，其他類等比減少。**總件數與稀有度機率完全不變**，所以不需要平衡數值。換上的道具從**下一次記帳**起生效。

### 3.5 品項與圖鑑（✅ 96 種起，owner 2026-11-24）

每類 12 種品項：尋常 6、罕見 4、奇珍 2，共 **96 格**。程式抽品項，LLM 把它寫成獨一無二的一件，例如「成冊的」變成［破舊的字典］。**格子有限，收藏無限**：點進一格看撿過的全部。

品項用**抽象的形**，才能套進任何世界觀（「成冊的」在騎士是字典，在太空船 AI 是航行日誌）。下表是草案 💡，可逐項改：

| 分類 | 尋常（6） | 罕見（4） | 奇珍（2） |
|---|---|---|---|
| 發光 | 珠狀、條狀、片狀、環狀、成束、碎屑 | 火苗狀、花苞狀、液態、結晶 | 星芒、影中的光 |
| 聲響 | 搖的、敲的、吹的、撥的、轉的、殼狀 | 會回聲的、會哼唱的、成對的、只響一半的 | 收著人聲的、無聲的樂器 |
| 字圖 | 成冊的、單張的、捲起的、折起的、成條的、刻上去的 | 畫了圖的、蓋了印的、殘缺的、密文的 | 會改寫的、空白的 |
| 容器 | 瓶、盒、袋、罐、匣、筒 | 上鎖的、層層套的、莢、透明的 | 裡面比外面大的、打不開的 |
| 自然 | 石、葉、貝、羽、枝、硬果 | 化石、水晶、乾花、浮木 | 天外石、不凋之物 |
| 舊物 | 鑰匙、鈕扣、織物、飾物、票證、杯具 | 只剩一半的、信物、玩偶、眼鏡 | 寫著名字的、還有餘溫的 |
| 零件 | 齒輪、發條、螺絲、彈簧、槓桿、鉸鏈 | 羅盤、鐘錶、鎖芯、鏡片 | 自走的、停不下來的 |
| 謎物 | 方的、圓的、長的、扁的、軟的、多孔的 | 兩種觸感的、會變重的、看不到背面的、沒有影子的 | 像某段時間的、好像在等人的 |

**集滿時間**（模擬 3,000 次，每日一萬步＝約 5.4 件，含奇珍保底）：

| 種類 | 一半 | 九成 | 全滿中位數 | 八成的人 |
|---|---|---|---|---|
| 48 | 7 天 | 27 天 | 59 天 | 40～94 天 |
| **96** | 13 天 | 52 天 | **143 天** | 100～216 天 |
| 192 | 26 天 | 102 天 | 341 天 | 251～491 天 |

- 擴充**只增不刪**，品項 id 永不重用；可分季增加或加新類。已集滿的舊套標「已完成」，不讓人覺得倒扣。
- 圖示可分批畫（先 48 個）。還沒畫的品項先用分類圖示。
- 只面向台灣／繁中，不做多語（✅）。

## 4. 揭曉

### 4.1 流程

1. 點開，程式依道具 id 決定角落與「發現經過」，重試不變、不必存檔。
2. 分類、稀有度、圖示立刻出現，同時呼叫 LLM。
3. 回應寫入道具後，顯示名稱、故事、說明文字效果。
4. 自動收進道具欄；使用者可聊聊、返回或丟掉。

**不抽吉凶**（✅ 2026-11-24 拿掉：只影響語氣，卻讓人想丟掉「凶」的東西）。改用六種不分好壞的「發現經過」，只讓故事不重複，不顯示在畫面上。運氣留給「用用看」。

### 4.2 LLM 要寫什麼

| 欄位 | 限制 |
|---|---|
| 名稱 | 2～12 字 |
| 發現故事 | 2～3 句，發現者口吻，發生在角色自己的世界 |
| 地點 | 角色世界裡的地點，一小句 |
| 說明文字效果 | 一句沒用但有趣的效果，例如「帶在身上心情會變好。效果無法驗證。」 |

給模型的條件：發現者、分類說明、稀有度、發現經過、當天天氣（有才給）、心情標籤（有且同意才給）。

**不給**：步數、距離、身高、真實地點、新聞、使用者的心情文字。步數等資訊由程式印在卡片上。

效果不得宣稱療效，也不得承諾機率或程式沒有的功能。

### 4.3 失敗與備援

- 不連網、沒有 API Key、逾時或格式不符：**道具不掉**，停在「待生成」並可重試。
- 內建備用名稱，例如「還說不清的發光物」。道具照樣留著，日後再生成。
- 要擋沒有金鑰時用 `hasUsableApiKey()`；逾時走 signal（見 `CLAUDE.md` §5）。

### 4.4 為什麼點開才生成

| 做法 | 問題 |
|---|---|
| 撿到當下 | 違反背景不呼叫 LLM |
| 開 App 批次 | 沒點開也花錢，還會跟散步發話撞在一起 |
| **點開才生成** | 費用由使用者控制，只需等幾秒 |

## 5. 卡片上的客製化資訊

| 資訊 | 來源與精確度 |
|---|---|
| 發現者 | 記帳時抽的角色 |
| 日期 | **只準到日**；現有資料是每日彙總，不知道幾點撿到 |
| 步數 | 那次記帳後的當日步數，由程式印上，不進 prompt |
| 地點 | **角色世界裡的地點**，由 LLM 寫，不代表真實位置 |
| 天氣 | 記帳當下的狀況與氣溫（§6） |
| 心情 | 對應撿到日期的心情（§8） |

**真實地點**：與 walk 設計 §1「不做 GPS、地點打卡」、§9「完全不取用定位」、§8「不給縣市」衝突，而且背景撿到時根本不知道位置。背景定位還要 Play 的聲明、示範影片與審查。因此採角色世界的地點（💡，若要改是推翻既定決定）。

## 5.1 今日旅途（✅ 5 組風格包，owner 2026-11-24）

入口畫面是一條小路，角色在前方，小包散在路上。**用 SVG 元件拼，不用整張地圖，也不生圖**。

- **骨架**（共用）：6 種路線、小包位置、天氣（晴、陰、雨、霧）、時段（清晨、白天、黃昏、夜晚）。
- **風格包**（換佈景）：每包 4 個場景，共 20 個。組合數 6 × 20 × 4 × 4 ＝ 1,920。

| 風格包 | 場景 | 路邊的光源 |
|---|---|---|
| 現代 | 巷弄、公園、河堤、商店街 | 路燈 |
| 科幻 | 艙道、星港、溫室艙、外星荒原 | 導引燈條 |
| 西方奇幻 | 城牆、森林、市集、高塔 | 火把 |
| 東方古風 | 山徑、渡口、庭院、夜市 | 燈籠 |
| 夢境（備援） | 雲上、書海、花田、水面 | 漂浮的光 |

- **LLM 只從清單挑，不畫圖**：每位角色問一次（送角色卡，費用一次），最多挑兩包，結果存起來。使用者可手動改；角色卡改了可重選。
- 看不出世界觀、沒網路、沒金鑰或失敗：用夢境。
- 同行多位角色時**每天輪一位**的世界。
- 當天組合以**日期**固定，重開不變；天氣用當天存下的狀況，沒有就用晴；走得越多，路延伸越長。
- 不代表使用者真實走過的地方。
- 深色主題與 12 組配色都要能看；**尚未設計**。

## 6. 天氣與新聞

**天氣：第一步就做**（💡）。記帳時若是當天步數，且使用者已開啟天氣，就存當下狀況＋氣溫；沿用 walk 設計 §8 的不含地名版本。補算過去日期的道具不附天氣。不代表走路當時的天氣。

**新聞：延後，獨立開關、預設關**（💡）。
- 由**使用者在新聞頁挑一則**「變成下一件道具的靈感」，不自動抓新聞。
- 含縣市的標題**由程式擋下**，不破壞既定限制。
- 災難、命案等題材要能避開，不能只靠 LLM 判斷。
- 兩者都只影響名稱與故事，**不影響稀有度或機率**。

## 7. 道具怎麼玩

### 7.1 聊聊這個

- 可帶 **1～3 件**，按下就能聊，**不要求使用者打字**；想補一句話再補。
- 預設在目前對話。發現者不在場也能聊，內容會註明是誰撿到的。
- 名稱與故事直接寫進那則訊息，因此會跟著對話、摘要、S2 對話同步走。
- 沒聊過的道具，角色**不會主動提起**，避免每次對話都佔 token。
- 從道具欄選道具和角色聊，以及一起聊多件：✅；其餘細節：💡

### 7.2 使用

> ✅ 2026-11-25 owner 定案改成**籤語版**（見 §15.6）：每件 1 次，程式抽一句幸運符／解答之書式的話，不呼叫 LLM。下面的六面骰與變樣是舊草案，暫不做。

一顆按鈕，不用打字，**沒有任何數值加成**。擲一顆六面骰，目前對話中的一隻角色直接演出來。

| 骰面 | 會怎樣 | 道具會變嗎 |
|---|---|---|
| 1 | 出包 | 會，變樣 |
| 2 | 沒反應 | 不會 |
| 3 | 引來什麼 | 不會 |
| 4 | 意外有用 | 不會 |
| 5 | 有新發現 | 不會，說明多一句 |
| 6 | 奇蹟 | 會，變樣 |

例：［破舊的字典］擲到 1 變［掉了幾頁的字典］，擲到 6 變［會自己翻頁的字典］。

- **每件共 3 次**，用完移到「紀錄」。限次、用完變成紀錄：✅；次數 3：💡
- 每件最多變樣一次；3 次內至少變一次的機率約 70%。之後仍可用，只演故事不再改名。
- 1 不是懲罰：分類與稀有度不變，舊名與舊故事留在「來歷」。
- 骰面**先存檔再生成**，失敗不扣次數、也不能重骰。
- 演出、改名、一句話摘要在同一次 LLM 呼叫完成。

### 7.3 合成（後面的步驟）

- **一件道具只能當一次材料**，成為材料後移到「紀錄」：✅
- 只有同階能合成，最高三階（一階＋一階→二階；二階＋二階→三階）。三階需要 4 件原道具：💡
- 未揭曉、已用完的不能當材料；用過一兩次但未用完的可以。成品重新有 3 次。
- 成功才標記材料；合成前確認，**不能還原**，丟掉成品也不還材料。
- 每次只給 LLM 兩件直接材料，prompt 不會愈長愈大。
- 不抽稀有度、不佔 96 格，另放「合成品」區，卡片有來歷樹（存材料名稱快照）。

### 7.4 明確不做

> 戰鬥 2026-11-25 owner 改為要做，規格另見 `docs/walk-battle-design.md`（三回合過招，尚未實作）。

攻擊力、體力、等級、耐久、買賣、交易、付費、排行、種植、小隊；用道具增加撿取總數；`1d20` 檢定與修正值。

## 8. 每日心情（💡，獨立小功能）

想法是 owner 提出的（✅），以下規則待確認。

- 一天一筆：5 種表情，加一句可不填的話。當天可改，跨日鎖定。
- 沒走路也能記；沒記也沒關係，**不提醒、不算連續天數**。
- 道具依**撿到的日期**對應心情。後來才記的，卡片補上心情章；已生成的故事不重寫。
- 只把**標籤**給 LLM 調語氣，**那句話預設不送**。要求角色不評論、不診斷、不勸導。
- 送標籤前另外徵求同意。
- 以後可做月曆回顧，把心情、步數和撿到的道具排在一起；還能列出「帶著這件的 8 天裡 5 天記了開心」，只列次數、不說因果。
- 圖示用自己的 `MonoIcon`，畫面不仿照別的遊戲。

## 9. 照片（第一版不做）

「讀當天拍的照片」要的是**相簿讀取權限**；相機權限是用來拍新照片。

| 做法 | 權限 | 判斷 |
|---|---|---|
| 自動讀當天照片 | `READ_MEDIA_IMAGES` | Play 限系統選擇器不足以支援核心功能的 App，官方舉例是相簿類；判斷 DeST 很難通過 |
| **使用者用系統選擇器挑一張** | 不用相簿權限 | 後續優先。App 只看得到被選的那張 |
| 當場拍照 | 待查 | 不是當天既有的照片 |

照片送給雲端 LLM 會離開手機，可能含他人的臉、住家或文件，之後的保存由供應商條款決定。若要做：縮圖、移除 EXIF、送出前當下告知並取得同意，並檢查 Play 資料安全表。

## 10. 資料、記帳與同步

### 10.1 不可重複發

walk 記帳靠 `creditedByDay` 不重複計步，道具搭同一個機制：

- `creditSteps()` 依**舊→新**的日期，把每天的新增步數餵進進度；跨過門檻就產生一筆掉落。
- 進度、下一門檻、掉落**與 `WalkState` 同一次寫入**，不會只記步數卻掉道具，或反過來。重讀、資料晚到、跨日都不會多發。
- 掉落先放 `pendingDrops`，再搬進道具檔。搬移以掉落 `id` 去重，中途關 App 重做也安全。
- ⚠️ `normalizeWalkState()` 目前只保留已知欄位，新增欄位**必須同步加進去**，否則每次讀檔就消失。

```ts
// WalkState 新增
itemProgress: number            // 距上次撿到累積的步數
nextDropAt: number              // 這次的隨機門檻
dropsSinceRare: number          // 保底計數
pendingDrops: ItemDrop[]        // 尚未搬進道具檔

interface ItemDrop {
  id: string                    // 建立時產生，搬移去重用
  day: string                   // 歸屬日期（當地）
  category: ItemCategory
  kind: string                  // 品項 id，例 `ink.bound`；只增不重用
  rarity: ItemRarity
  finderId: string
  finderName: string            // 快照
  stepsToday: number            // 該日記帳後步數
  weather?: { description: string; temperatureC: number }  // 只有當天才有
}
```

### 10.2 道具檔 `modules/desktopst.walk/items.json`

```ts
interface WalkItem extends ItemDrop {
  status: 'unopened' | 'kept' | 'record'
  generation: 'none' | 'ok' | 'failed'
  tier: 1 | 2 | 3                         // 合成預留
  parents?: { id: string; name: string }[]
  usedInId?: string                       // 已成為哪件的材料
  mood?: string                           // 生成時用掉的標籤；顯示則依日期即時查
  name?: string; story?: string; place?: string; effect?: string
  history: { name: string; story: string }[]   // 變樣前的樣子
  usesLeft: number                        // 3
  useLog: { roll: number; summary: string; at: number }[]
  pendingUse?: { roll: number; messageId: string }  // 重試不重骰、訊息不重複
}

interface WalkCollection {
  items: WalkItem[]
  discovered: Record<string, number>      // 品項 id → 首次發現時間；丟掉仍保留
}
```

- 丟掉＝從 `items` 移除，並**記下已處理的 id**，以免掉落重送又長回來。
- 變更走 `updateWalkState` 同型的排隊，避免冷啟動與切回前景互蓋。
- `state-invalidated` 事件要推，否則畫面不更新（`CLAUDE.md` §5）。
- 心情另存 `modules/desktopst.mood/`，不綁步數模組。

### 15.7 角色前進（2026-11-25，owner 定案）

- **一萬步走完整條路，走到底折返**（✅）。不顯示圈數、百分比、還差幾步。
- **從站的地方依新增步數前進**（✅）。撿箱子就留在箱子旁，「先放著」也一樣；下次從那裡接著走。沒撿東西時位置等於今日步數。15.2 的「先放著就走回去」以本節為準。
- **換成另一張地圖或換日才回到上方**；同一張再選一次不重置。步數讀不到或變少都留在原地。換地圖後只算之後新走的。
- 箱子固定五個位置，不跟步數綁。從隊伍前方先放；收走的位置不立刻補，五個都收完才有「往前走」，只補箱子、隊伍不動。
- **在場的角色全部站出來**（owner 試玩：開四位只出現三位，說話的是沒站出來的那位）。三位一排，路的盡頭排成一列，最多六位；超過時發現者與遇到對手的人一定在畫面上。箱子跳到面前時顯示發現者的頭像，離席的人說故事也不會認錯。
- 隊伍共用一個位置，發現者走最前面，其他人晚一點跟上。站在箱子的另一側斜排。發現者不在場就直接跳出箱子，隊伍不動。角色高度由場景的 19% 改 16%，三位才不會蓋住箱子。
- 正在看箱子、等故事或過招時不移動也不換日，結束才補。開著 App 會在回到前景時重讀步數，每 30 秒看有沒有換日。
- 對手站在最近處的另一側，隊伍在最近處改往後排，不會疊在一起。過招不讀寫位置。
- 減少動態時直接站到新位置。「測試：走 2,000 步」讓畫面前進兩成，不動真正步數。
- 位置存 `modules/desktopst.walk/journey.json`，**只存本機**，清除陪伴同行資料時一併清掉。
- 程式：`core/walk/journey.ts`、`mobile/runtime/walkJourney.ts`、`mobile/ui/walk/road.ts`（`MAP_ROUTES` 移到這裡）、`Companion.tsx`。測試：`tests/mobile/walkJourney.test.ts`。
- 測試用的全角色包**只匯入手機測試版的資料**，沒有放進程式或 APK；發版不必清除，移除測試版 App 即一併刪除。
