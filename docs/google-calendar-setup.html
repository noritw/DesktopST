Google 日曆設定教學

讓 DeST 的角色知道你接下來的行程與待辦

啟用之後，角色在聊天時會知道你接下來的安排，可以自然提起 —— 例如「你明天早上九點有會，現在都兩點了」。

  • 全程唯讀：只會讀取，不會新增、修改或刪除你日曆上的任何東西。
  • 資料不經過第三方：你的電腦直接連 Google，作者看不到你的行程。
  • 這是進階功能，不設定完全不影響 DeST 的其他功能。

整個設定大約 10 分鐘，只要做一次。

為什麼要自己申請？不能內建嗎？

因為 Google 把日曆權限列為敏感範圍，有兩個限制：

  1. 內建的識別碼放進公開程式等於公開，任何人都能取出來用
  2. 未經 Google 驗證的應用程式上限 100 個使用者，額滿後所有人都連不上

要解除限制得由作者送 Google 驗證，需要隱私權政策、專屬網站與第三方資安稽核， 這違反 DeST「不需要付費給作者」的原則。

所以改成每個人用自己的 —— 額度是你自己的，也不會有人因為別人用光而連不上。 DeST 的 Spotify 功能也是同樣的做法。

1建立專案

  1. 開啟 Google Cloud Console，用你的 Google 帳號登入
  2. 點畫面上方的專案選單 → 新增專案
  3. 專案名稱隨便取（例如 DeST）→ 建立
  4. 建立完成後，確認上方的專案選單已切換到這個新專案
第一次使用會要求同意服務條款，照著點即可。不需要綁定信用卡。

2啟用兩個 API

日曆上的「行程」和「工作」在 Google 後端是兩套不同的服務， 兩個都要啟用，否則待辦事項會讀不到。

  1. 左側選單 → API 和服務 → 已啟用的 API 和服務
  2. 點上方 + 啟用 API 和服務
  3. 搜尋 Google Calendar API → 點進去 → 啟用
  4. 回上一頁，再搜尋 Google Tasks API → 點進去 → 啟用

3設定同意畫面

這是授權時會看到的那個畫面，Google 要求先設定好才能建立憑證。

  1. 左側選單 → API 和服務 → OAuth 同意畫面
    （新版介面可能叫 Google 驗證平台）
  2. 點 開始使用，依序填寫：
欄位填什麼
應用程式名稱DeST（隨便取，只有你自己會看到）
使用者支援電子郵件選你自己的信箱
目標對象選「外部」
聯絡資訊填你自己的信箱

勾選同意條款 → 建立。

4把自己加為測試使用者

這步不能跳過 沒做的話，授權時會直接出現「存取遭到封鎖」。
  1. 左側選單 → 目標對象（舊版介面叫 OAuth 同意畫面）
  2. 找到 測試使用者 區塊 → Add users
  3. 填入你自己的 Google 帳號信箱（就是日曆所屬的那個帳號）→ 儲存

5建立憑證，取得 ID 與密鑰

  1. 左側選單 → 憑證（新版可能叫 用戶端）
  2. 點 + 建立憑證 → OAuth 用戶端 ID
  3. 應用程式類型選 電腦版應用程式
    （依介面版本也可能顯示為「桌面應用程式」或「Desktop app」，是同一個）
  4. 名稱隨便填 → 建立
  5. 跳出的視窗會顯示兩串文字：
    • 用戶端 ID（結尾是 .apps.googleusercontent.com）
    • 用戶端密鑰

把這兩串複製下來。 視窗關掉也沒關係，之後在憑證清單點進去隨時能再看。

類型一定要選「電腦版應用程式」 選成「網頁應用程式」的話，授權時會出現 redirect_uri_mismatch 錯誤。

6填進 DeST

  1. DeST 設定 → 擴充 分頁
  2. 找到 Google 日曆 → 點 設定
  3. 把剛剛的 Client ID 與 Client 密鑰 貼進去
  4. 點 連結 Google 帳號，瀏覽器會自動打開
  5. 選擇你的 Google 帳號
  6. 會看到 「Google 尚未驗證這個應用程式」 的警告 —— 這是正常的， 因為這個應用程式是你自己剛建立的。點 進階 → 繼續前往（不安全）
  7. 確認權限清單（查看日曆、查看工作，都是唯讀）→ 繼續
  8. 瀏覽器顯示「已完成授權」就可以關掉，回到 DeST

設定視窗顯示 已連結：你的信箱，代表成功。

7確認真的讀到了

連結成功後，日曆設定視窗下方會出現 目前讀到的內容，並自動查詢一次。 框裡顯示的就是實際會送給角色的內容，例如：

[Calendar]
這是使用者本人的行程與待辦，已確實取得，可以自然提起。
今天 澆花（待辦）
明天 09:00–10:00 部門會議（會議室 A）
這個檢查不會發送訊息，也不會消耗 LLM 費用，隨時可以按「重新讀取」。
如果這裡有內容，功能就正常了。

⚠️ 重要：七天後要重新授權，除非做這一步

處於「測試中」的應用程式，授權每 7 天就會失效 也就是說每週都要重新連結一次。做完下面這步就不會了。
  1. 回到 Google Cloud Console → API 和服務 → OAuth 同意畫面
    （或 Google 驗證平台 → 目標對象）
  2. 找到 發布狀態，點 發布應用程式 → 確認

發布後狀態變成「正式版」，授權就不會每週過期了。

  • 仍然會顯示「未驗證」的警告畫面，這不影響使用
  • 使用者上限 100 人，你自己用完全不會碰到
  • 不需要送審、不需要付費

常見問題

授權時出現「存取遭到封鎖：這個應用程式的要求無效」

沒有完成步驟 4。回去把自己加進測試使用者，注意要填日曆所屬的那個帳號。

出現 redirect_uri_mismatch

步驟 5 的應用程式類型選錯了。刪掉重建一個「電腦版應用程式」類型的。

待辦事項讀得到，但沒有時間

這是 Google 的限制，不是 DeST 的問題。Google 工作（Tasks）的到期日 只儲存日期，時間會被丟棄，無法透過 API 讀取。 你在日曆上看到的「上午 9:00」是畫面排版位置，資料裡並不存在。

兩個做法：

  • 把時間寫進工作標題，例如 09:00 澆花 —— 標題讀得到，角色照樣講得出時間
  • 或改建成日曆「活動」而不是「工作」，時間就會完整保留（但失去打勾功能）

讀不到我另外建立的日曆

目前只讀取主日曆。如果你習慣把行程分在不同日曆，請回報。

角色說它看不到我的日曆

先看日曆設定視窗下方的「目前讀到的內容」：

  • 框裡有內容 → 讀取正常。角色否認多半是因為對話中先前已經說過「讀不到」， 模型會維持前後一致。開一個新對話再試，並且問「我今天有什麼事」而不是「你讀得到日曆嗎」
  • 框裡是空的或顯示錯誤 → 依錯誤訊息回頭檢查上面的步驟

怎麼停用？

設定 → 擴充 → Google 日曆，把開關關掉即可。 要完全撤銷授權就點設定視窗裡的 斷開連結， DeST 會通知 Google 撤銷權限並刪除本機憑證。

我的資料會被傳到哪裡？

只有你的電腦與 Google 之間。憑證以系統加密（Windows DPAPI）儲存在本機， 不會包含在備份或角色包匯出檔裡。行程內容會隨對話送給你自己設定的 LLM 服務商 （就像你打字說出來一樣），不會經過作者的任何伺服器。
