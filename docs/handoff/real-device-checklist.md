## 測試前準備

  （打包前先確認 `src/mobile/README.md` 那兩個陷阱：Capacitor 外掛要在

## 一、S2 M4 比對畫面（9 條）

- [v] 1. 獨立 → 遙控：比對畫面出現、左右各自可選、三顆快捷鍵、確認後電腦端**不長重複**

　結果：OK

- [v] 2. 遙控 → 獨立：同上，手機端不長重複

　結果：OK
　疑問：有些對話我的確想刪除，因為太沒意義，然而同步後又被另外一邊送回來，
　是否考慮新增刪除選項？但可能要做額外操作步驟或是警告危險色
　→ **本條驗證本身通過**；這個疑問是新需求，已收斂成待辦，見文末「本次測試結論」B-1

- [v] 3. 電腦上把某筆改名 → 比對畫面應仍配成同一列（靠 id）並標「電腦上叫⋯⋯」

　結果：配對本身 OK。附帶回報：某一兩則對話因為沒有用所以刪除，結果同步後又被補回來
　→ 同上，與第 2 條是同一件事，見文末 B-1

- [v] 4. 兩邊完全相同時：該分頁顯示「完全相同」，確認鍵變成「直接切換」
　結果：OK

- [v] 5. 比對畫面按取消 → **不應**出現「上次那台電腦連不上了」

　結果：OK

- [?] 6. 推情境後檢查電腦端 `scenes/*.json`：`activePersonaId` 要指向電腦上真的存在的 id，
  `desktopCharacters` 的座標要維持電腦原本的值

　結果：**`scenes/*.json` 本身沒實際檢查到，本條待補驗。**
　但測試過程中發現另一件事：某些對話的角色名稱在多同步幾次後掉了，
　不確定是在哪個階段掉的，**目前無法重現**。見文末 B-3

- [v] 7. **刪除**（2026-08-14 追加）：在電腦上刪掉一筆 → 手機比對畫面該列選「電腦」→
  按鈕與外框轉成警告色、副標變「刪除另一邊」→ 確認時跳出逐筆清單 →
  同步後手機那份真的消失。反方向（選「手機」刪掉電腦那份）同理

　結果：OK（角色／人設／世界觀／Lorebook／情境這些**資料分頁**的刪除都正常出現）
　⚠️ **這一條指的是資料分頁，不是對話分頁。** 原本寫得不夠清楚，owner 一度以為
　是在講對話而回報「沒有刪除功能」。**對話分頁本來就刻意沒有刪除語意**
　（`core/sync/convPair.ts` 檔頭「這個分頁不會刪任何東西」），不是漏做。
　對話要不要能刪是新需求，見文末 B-1

- [v] 8. 快捷鍵防呆：按「全部用電腦」不該產生任何刪除（單邊獨有的仍是補到對面）

　結果：防呆本身 OK（「全部用電腦」沒產生刪除）。
　但發現另一個 bug：**按「保留差異」不會把各列切到「不動」**。見文末 B-2

- [v] 9. **設定分頁**（S2 M5）：改電腦上的配色主題／對話限制／模組開關 → 開比對畫面
  「設定」分頁該欄位顯示不同 → 選一邊 → 同步後另一邊的值真的變成一樣，
  且**沒被選中的其餘欄位不受影響**（尤其驗證「對話限制」三欄只改一欄時，
  電腦端另外兩欄不會被送過去的請求覆蓋——見 `mobile-sync-m4-compare.md` §8.3）

　結果：OK

## 二、S2 M5 設定同步（6 條）

- [v] 1. 在電腦上改配色主題 → 手機比對畫面「設定」分頁該列顯示「電腦：〈新主題〉」

　結果：只會顯示所選的配色主題名稱

- [v] 2. 只選「對話限制」三欄裡的一欄用手機 → 同步後電腦上**其餘兩欄維持電腦原值**，
  不會被送出的請求覆蓋成手機的值

　結果：OK

- [v] 3. 切換供應商（選電腦） → 手機那個供應商如果原本沒設過模型，要補目錄預設值，
  不留空模型
　結果：如果同步完馬上點設定，會顯示載入設定失敗，其他地方例如角色也是。
  如果還沒載入完就不要給使用者按，或者是顯示一些載入中…的小動態，不要看起來像壞掉

- [v] 4. 模組開關（例如天氣）從電腦帶回手機 → 手機的天氣模組真的被打開，
  不是只有 `enabled` 欄位變了但功能沒生效

　結果：OK

- [v] 5. 兩邊設定完全相同時，「設定」分頁顯示「設定兩邊完全相同」

　結果：OK

- [v] 6. 快捷鍵「全部用電腦」只在設定分頁生效，不影響資料分頁的選擇，反之亦然

　結果：OK

> **補驗一條**（§8.5b，2026-08-14 owner 真機揪出來的漏網欄位）：
> 天氣的「潤飾」子設定（`weather.polish`，天氣訊息要不要先過一次輔助模型）
> 現在也在比對範圍內了。在電腦上把它切掉 → 手機比對畫面應該看得到這一列
> （歸在模組分組、列在天氣模組開關附近），選一邊後兩邊一致。
>
> 　結果：OK

## 三、對話同步（8 條）

> 出處 `mobile-mode-switch-sync.md` §8.4。**第 1 條最重要**——S2 M3 當初就是栽在
> 重複增生，最後要靠一次性腳本清電腦端資料才收拾掉。

　結果：OK

  **不是**「手機上獨有」

　結果：OK

- [v] 3. 兩邊各自在同一則對話裡聊幾句 → 合併後兩邊都看得到對方那幾句，
  而且**順序照時間戳交錯正確**，不是一邊接在另一邊後面

　結果：OK

- [?] 4. **帶圖片的對話**：手機上傳幾張圖 → 合併 → 電腦上圖片正常顯示
  （這條在驗分批：單則帶三張圖就可能自己超過一塊）

- [v] 5. 電腦上把某則對話改名 → 比對畫面該列應仍配成同一列，並長出「⚠ 標題兩邊

　結果：同步沒問題，但電腦上改對話名稱，上方標題列沒有即時更新

- [v] 6. 對話很多時（十幾則）確認畫面不會卡，且「另有 N 則兩邊相同」預設收起

　結果：OK

- [v] 7. 合併正在看的那則對話 → 手機畫面應立刻出現補進來的訊息（`state-invalidated`）

　結果：OK

　結果：OK

## 本次測試結論（2026-08-16，owner 於 Pixel 10a 實測）

**23 條全部測過，同步的核心行為沒有失敗**——最重要的那條（對話同步第 1 條：
同一則推兩次不能長出第二份）通過，S2 M3 的重複增生沒有重演。

唯一沒完成的是 **M4 第 6 條**（`scenes/*.json` 的欄位沒實際打開檔案檢查），
標成 `[?]` 待補驗。

以下是測試過程中新發現的問題，**都不是「該條驗證失敗」，而是順帶揪出來的**：

### B-1　對話刪不掉，同步後會被對面補回來 ← 新需求（owner 想做）
出現在 M4 第 2、3 條的附帶回報。現況是設計如此：`core/sync/convPair.ts` 檔頭
明文寫「某一邊少了幾則訊息一律當成『還沒收到』，補過去而不是刪掉對面」，
當初只考慮了「還沒收到」，沒考慮「使用者是故意刪的」。

owner 的需求分兩種、風險差很多，**建議拆開、先做安全的**：

1. **整則對話刪除**（建議先做）——單邊獨有的列現在只有「複製過去／不動」，
   加第三個「刪掉對面那份」。**完全複用資料分頁已驗證過的那套**
   （警告色外框、副標「刪除另一邊」、確認時跳逐筆清單），風險低。
2. **訊息層刪除**（建議延後）——兩邊都有、但手機上刪了某幾句要讓電腦也消失。
   危險得多：`merge` 的前提就是「缺的都補齊」，**光看指紋分不出差異是
   「新的」還是「被刪的」**。要嘛做墓碑紀錄（兩端都要存、要有清理策略、
   寫錯就是真的刪資料），要嘛在確認畫面把「將從電腦刪掉的 N 則訊息」
   逐句列出來再確認。owner 明確要求刪除前要能看到內容。

> 先做 1、用一陣子再決定要不要做 2。很可能「整則刪得掉」就解決八成困擾。

### B-2　「保留差異」快捷鍵沒把各列切到「不動」
M4 第 8 條發現。防呆（「全部用電腦」不產生刪除）是好的，壞的是這一顆。

### B-3　對話的角色名稱多次同步後會掉 ← **目前無法重現**
M4 第 6 條發現。沒有重現步驟就先擱著，硬查等於瞎猜。
**下次再遇到請記三件事**：①掉名字的是哪一則對話 ②當時是哪個方向同步
（手機→電腦還是反過來）③那則對話的角色在另一邊存不存在。

### B-4　同步完馬上點設定／角色會顯示「載入失敗」
M5 第 3 條發現。資料還沒載完 UI 就可以點，看起來像壞掉。
應該擋住操作或顯示載入中動態。

### B-5　手機上傳圖片送出後，第一時間看不到縮圖
對話同步第 4 條發現。角色有正確針對圖片回應，同步到電腦也正常顯示，
但要再同步回手機才看得到圖。像是本地上傳後沒做樂觀更新，**不是同步的 bug**。

### B-6　電腦上改對話名稱，上方標題列沒有即時更新
對話同步第 5 條發現。同步本身沒問題，是顯示層沒收到／沒重讀。
