# 陪伴同行（計步陪伴）設計草案

> 狀態：**程式寫完、原生層尚未編譯**（2026-11-23，分支 `feat/walk-together`，未合併）。
> 核心、runtime、設定頁有測試／瀏覽器驗證；Kotlin、manifest、gradle **一次都沒編譯過**，
> 因為寫的那台電腦沒有 Android 環境。接手步驟見 §13。
> 範圍：DeST 手機獨立版（Android）。桌面、遙控模式不做。
> 標「待驗」的是還沒實測的假設；§11 是要 owner 決定的事。

---

## 1. 要做什麼

使用者走了多少路，**目前對話裡的角色就在他們自己的世界裡走了一樣的路**。
角色由使用者自訂，世界觀無法預測，所以程式不預設路線、地點或劇情，
只提供「距離＋（選配）天氣」，由角色用自己的方式講出來。

- 騎士沿城牆巡邏、太空船 AI 陪你走完輪機艙走道，都由角色卡決定。
- 三隻角色同行，就是**三隻都走了全額**，不平分。
- 不限定用腳走：飛行、坐輪椅、住在螢幕裡的角色，都能「陪這段路程」。

**不做**：GPS、Google 地圖、地點打卡、帳號、排行榜、社交、防作弊、
連續天數獎懲、種植／小隊／佔領地圖等玩法、跨裝置同步。

## 2. 設計原則

1. **不懲罰**：步數少不扣東西，角色不責備、不催促。
2. **不武斷**：沒有步數可能只是沒帶手機，不可以說「你今天都沒動」。
3. **不代演**：不得虛構使用者的行為、感受、去過的地方。
4. **數字由程式算**，模型只負責講故事。
5. **讀不到不等於 0**：任何失敗都要顯示成失敗。
6. 整個模組**預設關閉**，關掉後不讀步數、不生成。

## 3. 步數來源

### 3.1 用 Health Connect 的彙總查詢

- 權限只要 `READ_STEPS`；不宣告、不寫入其他健康類型
  （食記的 manifest 有完整的 `tools:node="remove"` 清單可參考）。
- **必須用 `aggregate`（`StepsRecord.COUNT_TOTAL`）**，不要讀出逐筆資料自己加總。
  手機和手錶會同時寫入，彙總才會處理重疊。
- 不指定資料來源，讓系統把手機內建步數一起算進去。

⚠️ **不要沿用食記 `nutrition/mobile/src/health.ts` 的讀法**。那條路走
`@capgo/capacitor-health` 的 `readSamples()`，踩過「湊滿 `limit` 就停止翻頁，
整天只加到清晨」的坑，而且自行加總也不會去重。
該外掛有沒有提供步數彙總「待驗」；沒有就自己寫一支小的 Kotlin 外掛。
我傾向**直接寫 Kotlin**：小工具本來就要在原生端讀，兩邊共用一份讀取程式碼。

### 3.2 沒有手錶的人

| 狀況 | 預期 |
|---|---|
| Android 14＋且 SDK extension ≥ 20 | Health Connect 可由手機本身計步 |
| 較舊系統 | 要有其他 App（如 Samsung Health）寫入 |
| 手機沒帶在身上 | 不會計到，無法補救 |

- 手機計步要**至少一個 App 取得 `READ_STEPS` 後才會啟動**，授權前的步數不保證有。
- 貼身帶著走通常夠用，放桌上、推車上會漏算。
- **第一版只接 Health Connect**。有實際使用者讀不到，再評估 Google 的 Recording API
  備援；屆時一天只採用一個來源，**兩個來源不可相加**。

### 3.3 更新延遲

手錶步數要先同步到手機才看得到，晚到的資料會讓當天總數之後變大，
§5 的記帳方式必須容許這件事。

## 4. 距離

- 第一版一律用「**步數 × 步幅**」，只需要步數權限，規則單純且不會混到騎車。
- 步幅依序取：**自訂步幅 → 身高 × 0.415 → 預設 0.70 公尺**
  （自訂合理範圍 0.3–1.2；身高 100–230 cm 以外不採用）。身高換算只是一般估算。
- 顯示到 0.1 公里並加「約」：6,000 步＝約 4.2 公里。
- 給模型的「約 N 分鐘路程」以每小時 4.5 公里換算，**明講可能是分段走的**。

### 4.1 身高怎麼來

食記與 DeST 是**兩支獨立的 App**，資料放在各自的沙箱，DeST 不能直接讀食記的
`bodyProfile.heightCm`，所以一定要有使用者同意的傳遞動作。

開啟模組時顯示一次，設定頁之後隨時可改：

> **身高（選填）**
> 只用來估算你的步幅，把步數換算成距離。只存在這支手機，不會傳給 AI 或角色。
> 不填也能使用，會以一般步幅計算。
>
> `[　　] cm`　　〔從食記帶入〕　　〔略過〕　〔儲存〕

- 〔從食記帶入〕只有偵測到手機裝了食記才出現；沒裝就只有手填，**略過後不再追問**。
- 帶入流程：DeST 明確指定食記套件開啟 → 食記顯示「要把身高 170 cm 提供給 DeST 嗎？」
  → 同意 → 以 Activity result 交回 → DeST 填入欄位，使用者按儲存才生效。
- 只傳身高一個欄位，不帶體重、年齡、性別等。不放進網址（深連結可能被別的 App 接走）。
- 食記**沒存過個人資料時要回「尚未設定」**：表單的 170 是預設顯示值，不能當成使用者的身高。
- 取消、版本太舊不支援、尚未設定，都退回手填，不算錯誤。
- **帶入是一次性的**，之後兩邊各自獨立，食記改了不會自動跟著變。
- 不用 ContentProvider＋簽章權限：GitHub 版與 Play 版簽章可能不同，會時好時壞。
- 兩支 App 都要改（食記新增同意畫面並發新版、DeST 宣告 `<queries>`），
  所以**先做手填，帶入隨後補上**，不擋第一版。

不讀 Health Connect 的 Distance：多一個權限，還要排除騎車，陪伴用途不值得。

## 5. 記帳規則

### 5.1 顯示用與記帳用分開

- **今日步數**：當地午夜到現在的彙總值，直接顯示，小工具與 App 一致。
- **同行里程**：記在各角色身上，只由 App 寫入。**小工具永遠唯讀**，
  避免背景與前景兩個程序同時改同一份檔案。

### 5.2 怎麼分給角色

每次讀取時，對上次讀取那天到今天的每一天：

```text
本日新增 = max(0, 本日彙總 − 本日已記帳)
本日新增 → 全額記給「讀取當下」目前對話的所有角色
本日已記帳 = max(本日已記帳, 本日彙總)
```

- 晚到的手錶資料會自然補上；來源修正而變少時不倒扣。
- 最多往回補 **7 天**（Health Connect 預設只能讀約 30 天）。
- 中途換角色但沒開過 App，那段會算給開啟時的角色。刻意不追溯，規則簡單。
- **首次啟用**以當下步數為起點，不把啟用前的步數記給角色。
- 讀取失敗時什麼都不改。同一時間只允許一個記帳程序（session 內互斥）。
- 日期一律用裝置當地日期；時區改變後以新的當地日界線為準。

### 5.3 資料

`modules/desktopst.walk/` 底下：

```ts
interface WalkSettings {
  enabled: boolean              // 預設 false
  heightCm?: number             // 選填，只用來算步幅
  strideMeters?: number         // 選填，使用者自訂時優先於身高
  heightPromptDone: boolean     // 填過或略過就不再問
  speakOnOpen: boolean          // 預設 true（模組開啟後）
  includeWeather: boolean       // 預設 true；仍受既有天氣開關約束
  minStepsToSpeak: number       // 預設 1500
  minIntervalMinutes: number    // 預設 120
  maxPerDay: number             // 預設 3
}

interface WalkState {
  creditedByDay: Record<string, number>      // 保留最近 8 天
  byCharacter: Record<string, { totalSteps: number; since: number }>
  initialized: boolean                       // 首次只建立起點
  pendingByDay: Record<string, number>       // 尚未拿來講的步數，按日分開
  recentThemes: string[]                     // 避免題材重複
  lastSpokenAt: number
  spokenDay: string
  spokenCount: number
}
```

里程存步數，不存公尺，改身高或步幅時距離會一起重算。角色刪除時清掉對應里程。

## 6. 小工具

獨立的一個小工具，不併進既有對話小工具。

```text
┌────────────────────────────────┐
│ (大頭)(大頭)(大頭)     6,000 步    │
│                        約 4.2 公里 │
│ 更新於 14:32                  ↻  │
└────────────────────────────────┘
```

- 頭像沿用 `DeSTWidgetProvider.kt` 的 bitmap 畫法，顯示目前對話成員，
  最多 3 個，其餘顯示「+2」。
- 名單與頭像由 App 端快照提供（比照 `widgetBridge.ts`），步數由原生端自己讀。
- 配色與透明度沿用 DeST 小工具的設定，不另開一套。
- 點擊開啟 App。

| 狀態 | 顯示 |
|---|---|
| 正常 | 步數、距離、更新時間 |
| 讀取成功且真的是 0 | 0 步 |
| 模組關閉 | 尚未開啟「陪伴同行」 |
| 沒有權限 | 點此授權 |
| 沒有 Health Connect 或版本太舊 | 這支手機無法計步 |
| 讀取失敗 | **保留上次數字**＋「更新失敗」 |
| 跨日後還沒讀到 | 不沿用昨天的數字，顯示「等待更新」 |

**更新時機**：開 App、按 ↻、系統定時更新（最短約 30 分鐘）。
不會即時跳動，所以「更新於」一定要顯示。

**背景讀取權限要申請**（owner 2026-11-23 拍板），小工具才不會一直停在舊數字。

- 權限是 `READ_HEALTH_DATA_IN_BACKGROUND`，使用者要另外同意；先檢查裝置是否支援。
- 啟用流程先要步數、再要背景讀取，並說明「讓小工具不開 App 也能更新」。
- 拒絕或不支援時功能照常：↻ 改成開啟 App 更新，小工具提示「開啟 App 更新」。
- **背景只讀步數、更新小工具**，不記帳、不呼叫 LLM、不啟動 WebView。
- 開 App 時一律馬上重讀，跟有沒有背景權限無關。讀完前先顯示上次數字＋「更新中」。
- 背景更新仍受系統省電限制，做不到即時；手錶沒同步過來的步數也讀不到。

## 7. 開 App 時角色回應

### 7.1 流程

```text
回到前景 → 讀步數、記帳、刷新小工具（每次都做）
        → 通過下列條件才呼叫 LLM → 角色說話
```

| 條件 | 預設 |
|---|---|
| 距上次講完的新增步數 | ≥ 1,500（約 1 公里） |
| 距上次發話 | ≥ 2 小時 |
| 今日次數 | ＜ 3 |
| 正在生成、打字或剛聊過天 | 這次不說，步數留著 |

門檻、間隔可設為 0，上限可調，想每次都說的人自己放寬。
聊天畫面另有「**聊聊剛才的散步**」按鈕，不受上述三個條件限制；
沒有新增步數時以今日累計為準，今日也是 0 就停用。

**只有生成成功才**清掉這次用掉的 `pendingSteps` 並增加次數。
生成期間新走的步數要留下，所以是扣掉「開始生成時的量」，不是直接歸零。
`pendingSteps` 跨日保留，但超過 7 天的部分不再講。

### 7.2 跟既有主動發話合併調度

`session.ts` 的 `runProactiveGreetingsHeadless()` 目前是「天氣 → 今日問候，只講一個」。
散步加在同一條順序裡，**一次開 App 最多講一則**：

> 天氣／地震事件 → 今日初次問候 → 散步

- 散步沒講到就留著下次講，不會遺失。
- 「今日問候帶入昨日步數」留到後續版本，第一版不改問候內容。
- ⚠️ 這支**同時被小工具觸發的 headless 呼叫**。散步只能在前景 App resume 走，
  headless 要明確跳過；否則使用者沒開 App 也會自動生成並花錢。

### 7.3 發話管線

沿用 `reminderSpeak.ts` 的虛擬提醒：新增 `speakWalkTogether()`，與
`speakWeatherEvent()`、`speakMorningBriefing()` 同型，落地與表情都不另寫。

- 多角色同行時**只生成一次，由一隻代表開口、隨機挑選**；同伴的名字給模型參考。
  是否同框、怎麼互動，由角色卡決定。
- 「三隻都說話」是後續選項，費用會乘上人數。
- 失敗就安靜略過，不要用快取的提醒離線台詞代替。

## 8. 給模型的內容

```text
[陪伴同行]
使用者與「A、B、C」從上次聊到現在，一起走了約 4.2 公里
（約 55 分鐘的步行路程，可能是分段走的）。
目前天氣：小雨，22°C。僅供氣氛參考，不代表走路當時的天氣。

請由 {{代表角色}} 用自己的語氣，說一件在自己的世界裡陪使用者走這段路時發生的小事。
- 題材：遇到某個人
- 依角色的世界觀與能力表現，不一定是用腳走
- 路程規模要與距離相稱
- 天氣不符合世界觀時，轉化或忽略
- 不要虛構使用者的行為、感受或去過的地方
- 不要評論走得多或少，不要催促
- 不要條列數據；2～4 句
```

- **題材**由程式隨機抽，避免天天「微風輕拂」，且不綁世界觀：
  遇到某人／撿到東西／走錯路／想起往事／看到沒見過的東西／跟同伴拌嘴
  （僅多角色）／休息一下／有點小麻煩。不與前兩次重複。
- **天氣只給天氣狀況與氣溫，不給縣市**。不能直接用 `getWeatherContextString()`，
  它的模板含地名，且 CWA 路徑給的是預報。要在 `core/weather` 新增一支
  只回傳狀況與氣溫的函式，並沿用現有快取。只有預報時就標成「預報」，不要標成「目前天氣」。
- 虛擬提醒維持 `injectWeather: false`，避免完整的 `[Weather]` 又帶進地名。
- **待驗**：對話上下文、角色卡或使用者人設本來就可能含地名，這裡只保證本功能不額外加入。

## 9. 隱私

| 資料 | 去處 |
|---|---|
| 原始步數、里程 | 只存本機 |
| 身高、自訂步幅 | 只存本機，**不進 prompt** |
| 約略距離（＋選配天氣） | 送到目前選用的 LLM 供應商 |
| 角色講出來的話 | 進對話，會跟著記憶摘要、S2 對話同步、匯出走 |
| 定位 | 本功能完全不取用（既有天氣的定位不受影響） |

- 開啟時用一段話講清楚上表，確認後才要權限；開 App 會**自動**送出也要寫明。
- 設定頁有「清除陪伴同行資料」，並註明**不會刪除已經講過的對話**。
- `modules/desktopst.walk/` 不進 S2、不進設定包匯出。
- ⚠️ `AndroidManifest.xml` 目前 `allowBackup="true"`，檔案可能進 Google 備份。
  若要主張「只存本機」，必須加備份排除規則（現況另需確認，建議與其他資料一起檢視）。
- Google Play 要填健康資料聲明、更新隱私權政策；Health Connect 還要求提供
  用途說明頁。GitHub APK 不受 Play 審查影響，但權限說明照樣要有。

## 10. 實作順序

1. **技術驗證**：Kotlin 讀當日彙總，做成除錯頁顯示數字與狀態，依下表實測。
2. **純邏輯**：`core/walk/`（記帳、距離、門檻、題材、prompt），配 vitest。
3. **小工具＋身高手填**：不接 LLM，先自用幾天。
4. **開 App 回應**：合併調度、天氣、設定頁。
5. **後續**：從食記帶入身高、里程碑、旅行手帳、問候帶入昨日步數、三隻都說話。

第 1 步沒通過就停，後面都不用做。

### 10.1 第 1 步實測

| # | 測法 | 通過標準 |
|---|---|---|
| 1 | 手錶＋手機同時帶，走 1,000 步 | 沒有變成約兩倍 |
| 2 | **取下手錶，只帶手機**走 1,000 步 | 與實數差 10% 內 |
| 3 | 手機留家，只戴手錶 | 同步後補得到 |
| 4 | 拒絕、之後撤銷權限 | 顯示未授權，不是 0 步 |
| 5 | 一支非 Pixel 手機 | 讀得到，或明確顯示無法計步 |

第 2 項代表一般使用者，最重要。

### 10.2 之後要有測試守住的事

- 重複讀取不重複記帳；資料晚到會補、變少不倒扣；跨日、跨多日、首次啟用。
- 三隻同行各得全額，換對話後只記給新成員。
- 生成失敗不扣 `pendingSteps`；生成中新增的步數不遺失。
- 一次 resume 只講一則；headless 不觸發散步。
- prompt 不含縣市名、身高。
- 步幅取用順序；沒填身高仍可換算；超出範圍的身高不採用。

### 10.3 工程注意

- 外掛動態 `import()`、不直接回傳 plugin 物件、逾時自己包（`CLAUDE.md` §5）。
- RemoteViews 的坑照既有小工具：圓形、按鈕要畫成 bitmap。
- **`minSdk`**：README 目前寫 Android 7.0 以上（24），與 Capacitor 8 預設一致；
  Health Connect 函式庫要 26（食記就是因此升的）。升級後 Android 7.x 裝不了新版，
  已安裝的舊版可續用但收不到更新；Android 8 以上不受影響，資料不會不見。
  README 的系統需求要同步改。`android/` 的 gradle 檔不在版控裡，改動要寫進
  產生 android 專案的流程（`scripts/prepare-android.mjs`），否則重建就不見。
- 這跟「第一版排除自動發話」不同，比照已開放的天氣發話與問候視為例外，

## 13. 接手：編譯與裝測試版

在平常打包 APK 的電腦：

1. `git fetch`、切到 `feat/walk-together`、`npm install`。
2. 手機接 USB，跑 `npm run apk:walk-test`。
   產出 `out/apk/DeST-walktest.apk`，套件名 `tw.nori.dest.walktest`、名稱「DeST 測試」、
   橘底 TEST 圖示，**與正式版並存，不會動到正式版資料**。不要用 `MobileST.bat` 的 [1]／[4]。
3. 裝好先確認套件名：`adb shell pm list packages tw.nori.dest` 要看到兩個。
4. 測試版裡不要開提醒、天氣主動發話、今日問候，以免跟正式版重複。
5. 選單 →「陪伴同行」→ 開啟 → 授權 → 桌面加小工具 → 照 §10.1 測。

編譯時最可能要修的：`HealthConnectFeatures` 在 connect-client 1.1.0 是否需要 `@OptIn`；
Kotlin 與 coroutines 1.11.0 的版本相容（照抄食記的設定）。

注意：

- `prepare-android.mjs` 會改**不進版控**的 `build.gradle`／`variables.gradle`
  （加 Health Connect 依賴、`minSdk` 至少 26）。切回 `main` 後這些改動仍在那台電腦上；
  要打正式版前先把 `build.gradle` 尾端那兩段與 `minSdk` 還原，或先備份這兩個檔再開始。
- manifest 的健康權限在分支上就會進正式建置，**合併前要先處理 Play 的健康資料聲明**。

與前面設計不同的地方：

- 「聊聊剛才的散步」按鈕放在陪伴同行頁，不在聊天畫面。
- 授權是一次同時要步數與背景讀取，由系統畫面讓使用者分開勾選。
- 小工具讀到「沒有任何資料」時顯示 0 步（與真的 0 步無法區分，待真機看需不需要分開）。
- 備份排除規則（§9）與從食記帶入身高（§4.1）還沒做。
