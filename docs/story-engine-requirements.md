## 問題背景

### 當前痛點

使用者在使用 DesktopST 進行 AI 角色扮演和 TRPG 時遇到以下問題：

1. **創作負擔重**
   - 使用者需要自己設計所有劇情細節（場景、事件、NPC、對話）
   - 即使只有大方向（如「冒險中確認心意」），也需要手動編寫每個場景
   - 長時間當 GM 很燒腦，無法享受「探索未知」的樂趣

2. **缺乏劇情結構**
   - AI 只會「反應」使用者的輸入，不會「主動推進」劇情
   - 沒有整體劇情進度概念，無法做到起承轉合
   - 事件缺乏邏輯連貫性，無法服務於故事目標

3. **探索樂趣矛盾**
   - 當使用者 = 世界建構者時，所有內容都是已知的
   - 真人 TRPG 中「GM 準備劇本，玩家探索」的體驗無法實現
   - 使用者想「旁觀角色互動」，但又必須自己推動劇情

4. **內容無法分享**
   - 創建的劇情只能自己玩，無法分享給朋友
   - 別人無法輕鬆創建自己的劇情內容

### 典型使用情境

#### 情境 1：創作輔助
```
使用者想寫故事：
「男女主角去冒險，最後確認心意」

但卡在：
- 去哪裡冒險？
- 遇到什麼人？
- 發生什麼事件？
- 如何鋪陳感情線？

期望：
AI 根據大方向自動生成完整劇情，使用者可以「體驗」而非「編寫」
```

#### 情境 2：單人 TRPG
```
使用者想玩 TRPG：
「我想體驗一個有起承轉合的冒險故事」

但現狀：
- 所有內容都是自己輸入的，沒有未知感
- AI 不會主動推進劇情，變成使用者當 GM

期望：
AI 自動當 GM，生成事件和轉折，使用者只需回應
```

#### 情境 3：內容分享
```
使用者創建了有趣的劇情：
「空島墜落，選擇與命運」

想要：
- 分享給朋友玩
- 朋友玩出不同的結局
- 朋友也能創建自己的劇本

現狀：
沒有打包和分享機制
```

## 核心需求

### 需求 1：保留未知感（自己玩不無聊）

**描述**：使用者創建劇本時，細節由 AI 生成並隱藏，使用者遊玩時仍有探索樂趣。

**關鍵點**：
- 使用者只輸入「大方向」（概念、主題）
- AI 生成完整劇情，但細節對使用者隱藏
- 遊玩時逐步揭露，製造驚喜

**範例**：
```
輸入：「冒險中確認心意」
AI 生成（使用者看不到）：
- 第 1 章：酒館接委託
- 第 2 章：遭遇強盜，男主受傷
- 第 3 章：古代遺跡解謎
- 第 4 章：BOSS 戰告白
- 結局：約定一起旅行

使用者遊玩時才知道具體內容
```

### 需求 2：多樣化結果（別人玩出不同體驗）

**描述**：同一個劇本，不同玩家會因選擇和運氣獲得不同體驗。

**關鍵點**：
- 關鍵選擇點影響劇情走向
- 隨機事件增加變化性
- NPC 關係系統影響結局
- 支援多重結局

**範例**：
```
玩家 A：選擇信任 NPC → 結局：攜手離開
玩家 B：選擇懷疑 NPC → 結局：孤獨離開
玩家 C：觸發隱藏事件 → 結局：成為島的守護者
```

### 需求 3：簡單創建與分享（UGC 平台）

**描述**：任何人都能輕鬆創建劇本，並分享給他人。

**關鍵點**：
- 創建流程簡化（5 分鐘完成）
- 提供多種創作模式（全 AI、半自動、手動）
- 劇本可打包成檔案（.dstpack）
- 支援本地分享（傳檔案）
- 未來支援線上社群

**範例**：
```
創作者：
1. 輸入概念
2. 選擇長度和類型
3. 點擊「生成」
4. 導出 .dstpack 檔案

分享：
傳給朋友 → 朋友載入 → 開始遊玩
```

## 使用者故事

### 作為創作者

**US-1**：快速創建劇本  
> 作為創作者，我想用一句話描述故事概念，讓 AI 生成完整劇本，這樣我不用花時間寫細節。

**US-2**：選擇創作深度  
> 作為創作者，我想選擇「完全 AI 生成」或「手動編輯」，這樣我能根據需求控制創作程度。

**US-3**：預覽與調整  
> 作為創作者，我想預覽 AI 生成的大綱，並在必要時調整，確保符合我的期望。

**US-4**：導出分享  
> 作為創作者，我想把創建的劇本導出成檔案，分享給朋友或上傳到社群。

**US-5**：保留未知感  
> 作為創作者，我想選擇「不預覽細節」直接導出，這樣我自己玩也會有驚喜。

### 作為遊玩者

**US-6**：載入劇本  
> 作為遊玩者，我想載入別人分享的劇本檔案，開始遊玩。

**US-7**：沉浸式體驗  
> 作為遊玩者，我想讓 AI 自動推進劇情，我只需要做選擇和回應。

**US-8**：做出選擇  
> 作為遊玩者，我想在關鍵時刻做出選擇，影響劇情走向和結局。

**US-9**：多周目探索  
> 作為遊玩者，我想玩多次同一劇本，探索不同分支和結局。

**US-10**：查看進度  
> 作為遊玩者，我想知道當前劇情進度和 NPC 關係狀態（如果創作者允許顯示）。

### 作為系統管理者

**US-11**：劇本驗證  
> 作為系統，我需要驗證劇本包的完整性和相容性，確保能正常執行。

**US-12**：進度儲存  
> 作為系統，我需要記錄玩家的遊玩進度，支援存檔和讀檔。

## 功能需求

### F-1：劇本生成系統

#### F-1.1：AI 大綱生成器
- **輸入**：故事概念（文字）、主題標籤、長度選擇、調性選擇
- **處理**：呼叫 LLM API 生成結構化大綱
- **輸出**：章節列表、NPC 列表、事件時間線、分支邏輯

#### F-1.2：三種生成模式
- **完全 AI**：只需輸入概念，全部由 AI 生成
- **AI 輔助**：使用者提供框架，AI 補完細節
- **手動創建**：使用者完全手寫（類似視覺小說編輯器）

#### F-1.3：大綱預覽與編輯
- 顯示章節標題、目標、預估時長
- 允許調整章節順序、新增/刪除章節
- 允許鎖定/解鎖特定元素（如必須出現某個事件）

### F-2：劇本執行引擎

#### F-2.1：自動劇情推進
- 根據當前進度自動觸發事件
- AI 生成旁白和場景描述
- NPC 自動產生對話和行動

#### F-2.2：事件排程器
- 按章節目標排程事件
- 根據進度百分比觸發高潮/轉折
- 支援隨機事件池（增加變化性）

#### F-2.3：Prompt 增強
- 自動注入當前章節目標、進度、關係狀態
- 隱藏未來劇情（對使用者隱藏，但 AI 知道）
- 維持 NPC 性格一致性

### F-3：分支與選擇系統

#### F-3.1：選擇點定義
- 創作者可定義關鍵選擇點
- 或由 AI 自動生成選擇點

#### F-3.2：分支邏輯
- 選擇影響 NPC 關係
- 選擇影響後續事件解鎖/鎖定
- 選擇影響最終結局

#### F-3.3：多重結局
- 支援 3-5 個不同結局
- 結局由「關係分數 + 關鍵選擇」決定
- 顯示結局收集進度（如 1/3）

### F-4：關係系統

#### F-4.1：NPC 好感度
- 每個 NPC 有獨立好感度（0-100）
- 對話和選擇影響好感度
- 好感度影響 NPC 行為和劇情

#### F-4.2：關係狀態追蹤
- 記錄重要互動歷史
- 根據歷史影響 NPC 態度

### F-5：進度管理

#### F-5.1：進度追蹤
- 當前章節、回合數
- 已觸發事件、已做選擇
- NPC 關係狀態

#### F-5.2：存檔系統
- 支援多個存檔槽
- 手動存檔 + 自動存檔
- 存檔包含完整狀態

#### F-5.3：回溯功能
- 允許回到關鍵選擇點
- 探索不同分支（可選功能）

### F-6：劇本包管理

#### F-6.1：劇本包格式（.dstpack）
- JSON 格式，包含：
  - 元數據（標題、作者、標籤、縮圖）
  - 劇本大綱（章節、NPC、事件）
  - 角色卡（可選綁定）
  - 隱私設定（顯示/隱藏選項）
- 加密未來劇情（防止意外劇透）

#### F-6.2：導出功能
- 將劇本打包成 .dstpack 檔案
- 包含所需角色卡和資源
- 生成分享碼（未來功能）

#### F-6.3：導入功能
- 載入本地 .dstpack 檔案
- 驗證檔案完整性
- 解析並加入劇本庫

#### F-6.4：劇本庫
- 顯示已安裝的劇本列表
- 顯示遊玩進度（未開始、進行中、已完成）
- 支援刪除、備份

### F-7：UI 組件

#### F-7.1：創作者工坊（Creator Workshop）
- 概念輸入介面
- 主題和調性選擇器
- 大綱預覽/編輯器
- 導出按鈕

#### F-7.2：遊玩介面（Story Player）
- 對話/事件顯示區
- 選擇按鈕（如果有選擇點）
- 劇情儀表板（可選顯示）：
  - 當前章節
  - 進度條
  - NPC 關係
  - 秘密計數

#### F-7.3：劇本庫介面（Pack Library）
- 劇本列表（卡片式）
- 載入新劇本按鈕
- 劇本詳情（元數據、預估時長）

## 非功能需求

### NFR-1：效能

- **劇本生成**：< 30 秒（中等長度劇本）
- **事件觸發**：< 2 秒（AI 生成事件描述）
- **載入劇本包**：< 1 秒

### NFR-2：可用性

- **創建劇本**：非技術使用者能在 5 分鐘內完成
- **遊玩劇本**：與現有聊天介面一致的操作邏輯
- **錯誤處理**：AI 生成失敗時提供重試或手動編輯選項

### NFR-3：相容性

- **劇本包版本**：向後相容（舊版劇本可在新版系統執行）
- **角色卡整合**：可使用現有角色卡系統
- **跨平台**：桌面版優先，手機版後續支援

### NFR-4：安全性

- **劇情加密**：防止意外劇透（簡單混淆即可）
- **檔案驗證**：防止惡意劇本包破壞系統
- **API 安全**：生成劇本時使用使用者的 API key

### NFR-5：可維護性

- **模組化設計**：Story Engine 作為獨立模組
- **可選功能**：非 TRPG 使用者可關閉此模組
- **文檔完整**：提供創作者指南和技術文檔

## 設計約束

### C-1：技術棧約束

- **前端**：React + TypeScript（與現有系統一致）
- **後端**：Electron Main Process
- **LLM**：使用使用者配置的 API（Claude、GPT、等）
- **儲存**：本地檔案系統（與現有 World/Character 一致）

### C-2：資源約束

- **本地生成**：不建立雲端後端（Phase 1-3）
- **API 成本**：生成劇本由使用者的 API key 承擔
- **儲存空間**：單個劇本包 < 5MB

### C-3：整合約束

- **角色系統**：複用現有 Character 系統
- **對話系統**：複用現有 Conversation 系統
- **使用者切換**：支援現有的「切換使用者身份」功能
- **World 系統**：劇本可綁定 World 設定（可選）

### C-4：使用者體驗約束

- **不破壞現有流程**：傳統對話模式仍可正常使用
- **可選功能**：使用者可選擇不啟用 Story Engine
- **漸進式學習**：從簡單到複雜的功能展示

## 成功指標

### M-1：核心功能達成

- ✅ 使用者能用一句話生成完整劇本
- ✅ 使用者遊玩時有「未知感」
- ✅ 同一劇本能玩出不同結局
- ✅ 劇本能導出並分享給他人

### M-2：使用體驗

- ✅ 創建劇本時間 < 5 分鐘
- ✅ 遊玩劇本時 AI 能主動推進（不需一直手動輸入）
- ✅ 劇情有起承轉合（不是隨機事件堆疊）

### M-3：技術品質

- ✅ 劇本包格式穩定，版本相容
- ✅ 劇情執行不出現邏輯錯誤（如 NPC 性格突變）
- ✅ 模組可開關，不影響非 TRPG 使用者

### M-4：社群效應（Phase 4）

- ✅ 至少 10 個使用者創建的劇本分享
- ✅ 每個劇本被遊玩 > 3 次
- ✅ 使用者回饋「有探索樂趣」
