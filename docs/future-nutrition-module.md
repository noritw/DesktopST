## 0. 一句話

可選模組：本機食物庫＋極簡入帳（關鍵字免 LLM／新食物才估價），
只追蹤**熱量與蛋白質**；**每日飲食列表**（翻日、合計、點名編主檔）；一眼快覽／小工具；
TDEE 建議但上限隨時手改；Health 讀寫皆選配；可只開飲食。換機靠搬家包與日後 S2。

## 1. 為什麼要做（owner 痛點）

- 每天拍照記飲食；Google 官方／訂閱制 AI 記帳難用、常要打一堆字、同一食物隔天熱量漂
- 已有 DeST 的 LLM Key／vision，不想再養一個獨立 App 佔空間、重接金鑰
- 角色頂多知道「愛吃／常吃什麼」，**不必記營養數字**
- 開源：Health 必須可完全不接；報表本機自算

## 3. 產品形狀

### 3.1 一 APK／一桌面程式、兩入口

- 虛擬 module id：`desktopst.nutrition`，預設**關**（第三層）
- 關模組 → 飲食 Icon、選單、Widget 全隱（`PackageManager` 停用元件）
- **只用飲食** → 可關聊天 launcher；開 App 進飲食；不需角色卡；只走關鍵字時可不填 API Key
- 不可兩入口都關到無法進入（保留設定內「恢復入口」）

### 3.2 極簡入帳

```
快覽／Widget → 快速入帳
  ├─ 關鍵字「三」→ 燻雞三明治／魚排三明治 → 點選代入（零 LLM）
  └─ 拍照（可選短註）→ 對庫命中則沿用；未命中才 LLM 估一次 → 入庫
```

硬規則：**庫內食物預設禁止 LLM 覆寫營養**（手編或明確「重新估價」才改）。

### 3.2b 每日飲食列表（MVP 主畫面之一）

進飲食入口後，**一顆按鈕**（或首屏主按鈕「今日紀錄」）打開全日列表頁——不是藏在設定裡。

**頁面內容**

| 區塊 | 內容 |
|---|---|
| 日期列 | 顯示目前日期；**上一頁／下一頁**切換不同曆日（無紀錄的日子顯示空列表＋合計 0） |
| 合計列（置頂或底部固定） | **今日總計熱量**、**今日總計蛋白質**（可並列相對上限／目標，超標紅字，與快覽同一套合計） |
| 餐次列表 | 每一筆：`時間`、`食物名稱`、`該筆熱量`、`該筆蛋白`（＝ FoodItem 每份 × 當次份量） |

**點食物名稱** → 進入該筆對應的 **`FoodItem` 詳情／編輯**（名稱、品牌、口味、營養、照片等）。  
同一 `foodItemId` 的多筆餐次**共用同一份食物資料**：在詳情改營養或名稱，之後所有引用該 id 的餐次顯示與合計一併跟著變（這正是「沿用同一份資料」的意義）。

列表列上另可提供次要操作（實作時）：改當次份量／時間、刪除該筆 `MealLog`——與「改食物主檔」分開，避免以為只改今天卻動到整庫。

**類似名稱怎麼辨別（是否顯示 ID／引用次數／上次食用）**

| 資訊 | 是否給使用者看 | 說明 |
|---|---|---|
| 內部 `foodItemId` | **預設不顯示**裸 UUID（難認、易誤導） | 進階／除錯可摺疊顯示短 id；日常靠下方欄位 |
| **品牌／店家／口味** | **列表副標必顯示**（有填才顯示） | 主辨識：「燻雞三明治 · 7-11 · 原味」vs「燻雞三明治 · 某咖啡 · 辣」 |
| **縮圖**（食物庫第 1 張） | 列表左側建議有 | 包裝類似時比文字更快 |
| **引用次數**（被幾筆 MealLog 使用） | **詳情頁＋關鍵字候選要顯示** | 「已記錄 12 次」→ 確認是常用那筆 |
| **上次食用時間** | **詳情頁＋關鍵字候選要顯示** | 「上次 昨天 12:30」 |
| 每份 kcal／蛋白 | 候選列與詳情顯示 | 同名不同熱量時一眼分開 |

資料上：`useCount`／`lastEatenAt` 可由 MealLog **聚合算出**（進 `core/`），不必強迫使用者手填；可選在 `FoodItem` 上快取並於入帳時更新以利排序。  
關鍵字候選與「今日列表」副標用同一套顯示規則，避免一邊分得出、一邊分不清。

若兩筆其實是不同食物卻曾誤绑同一 id：詳情提供「**另存為新食物**」（複製 FoodItem 新 id，可選是否把當筆 MealLog 改绑過去）。

### 3.3 角色邊界

- 可選注入極短 `[Food preferences]`（常吃／愛吃／忌口）
- **不**注入今日熱量／蛋白明細
- 飲食情境角色＝語氣／督促，不是帳簿 UI

### 3.4 LLM

- 共用 `llm.apiKeys`；模組自有 `nutrition.llm`（偏便宜 vision／文字）
- 與角色主模型分開；熟食重複記帳趨近零 token

### 3.5 Health（選配，兩層，皆預設關）

| 層 | 內容 |
|---|---|
| Health 讀 | 體重等 → `BodyProfile`（體重機→Google→Health Connect） |
| Health 寫 | 本機確認後的營養 log → Health Connect／手錶 |

模組本體不依賴 Health。開源使用者本機完整可用。Client ID 自備（若雲端 API）。

## 4. 資料模型（草案）

儲存根（桌面）：`%APPDATA%\DesktopST\modules\desktopst.nutrition\`  
手機：對應 `StorageAdapter` key（與桌面 schema 相同）。

| 實體 | 要點 |
|---|---|
| `BodyProfile` | 身高、體重、年齡、活動量、算出的 TDEE 快取、**dailyKcalLimit**、**dailyProteinGoalG**（後兩者一等可編） |
| `FoodItem` | id、name、aliases[]、brand、store、flavor、perServing{kcal, proteinG, …}、photoKeys[1..3]、source、updatedAt；**可快取** `useCount`／`lastEatenAt`（或由 MealLog 聚合） |
| `MealLog` | id、foodItemId、servings、eatenAt、note?、photoKey?（當次可選） |
| 模組 settings | enabled、nutrition.llm、healthRead/Write flags、入口／widget 開關 |

照片：資料目錄內相對路徑／key，**不進 APK**；壓縮後存。  
聚合／TDEE／關鍵字對庫／報表：`core/` 純函式（可測、可注入 `now`）。

## 5. 換機、同步、匯出匯入、手動編輯

換手機是 owner 明確需求：**第一期必須能搬家**，不能等 S2／雲端。

### 5.1 三層能力（由易到完整）

| 層 | 時機 | 做什麼 |
|---|---|---|
| **N1 搬家包匯出／匯入** | 飲食模組 MVP 必做 | 單一檔帶走食物庫＋照片＋餐次＋身體檔＋模組設定（不含 API Key） |
| **N2 手動編輯／修檔** | MVP | UI 編 FoodItem／MealLog／上限；進階可匯出 JSON 用外部編輯器再匯入（校驗 schema） |
| **N3 接 S2 點對點** | B7 之後接線 | 桌面↔手機手動推送／拉取／合併＋差異預覽；與角色資料同一套同步宿主 |

不做：雲端後端、連上就自動同步（S3）。

### 5.2 搬家包格式（N1）

建議副檔名：`.destnutrition`（實作可為 zip）。

```
manifest.json          # schemaVersion、exportedAt、appVersion
body-profile.json
settings.json          # 剝除任何密鑰
food-items/*.json      # 一食物一檔或單檔陣列
meal-logs/*.json       # 可按月分檔以免過大
photos/<foodItemId>/01.webp …
```

規則：

- **API Key 永不進包**（與 DST Pack／§4.7 一致）
- 匯入前預覽：食物 N 筆、餐次 N 筆、照片體積、schema 版本
- 匯入策略（使用者選）：
  - **合併**（預設）：同 `id` → mtime／updatedAt 較新者勝；新 id 追加；衝突列表可點選
  - **僅補缺**：只加入本機沒有的 id
  - **覆蓋本機飲食資料**：危險操作，二次確認
- 舊手機匯出 → 傳檔（雲碟／纜線／電腦中轉）→ 新手機匯入，**不需兩機同時在線**

桌面與手機都要有匯出／匯入入口（換機常經電腦中轉）。

### 5.3 手動編輯（N2）

- 食物庫：改名、別名、品牌／店家／口味、營養數字、增刪照片（1～3）
- 餐次：改份量、時間、換绑 FoodItem、刪除
- BodyProfile／日上限／蛋白目標：隨時改
- 「匯出 JSON 片段／整庫」給進階使用者；匯入時 **schema 校驗**，失敗不寫入
- 不提供無校驗的任意檔案覆蓋（避免弄壞帳簿）

### 5.4 與 S2 對接（N3）

當 B7 就緒，把 nutrition 納入同步清單：

| 資料 | 合併規則（草案） |
|---|---|
| `MealLog` | 以 id **聯集**（append-only 為主）；同 id 取 updatedAt 較新 |
| `FoodItem` | 同 id 取較新；衝突進差異預覽（名稱／營養／照片數） |
| `BodyProfile` | 較新者勝；**dailyKcalLimit／protein 手改**優先於單純 TDEE 快取欄 |
| 照片 binary | 隨 FoodItem 走；缺圖則標記待補 |
| API Key／Health token | **永不同步** |

換機推薦路徑（有電腦時）：舊手機 → S2 推到桌面 → 新手機 S2 拉；  
無電腦或不想開同步：走 N1 搬家包即可。

### 5.5 遙控模式過渡

S2 未完成前：若手機以遙控連桌面，飲食資料可先以**電腦為唯一真本**（薄客戶端讀寫），與現有設定／新聞報模式一致。獨立模式則靠 N1 搬家包。
