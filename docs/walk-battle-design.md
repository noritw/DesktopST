# 今日旅途：三回合過招設計

> 狀態：設計定案（owner 2026-11-25）。**§10 第 1～4 步與「聊聊」已實作、未 commit**，圖是佔位圖；圖鑑與美術未做。
> 前置：`docs/walk-items-design.md`（物品、今日旅途）。範圍同樣是 DeST 手機獨立版（Android）。
> 標記：✅ owner 明確說過或點頭／💡 依推薦，實作時可調。

---

## 1. 一句話

走在旅途上會遇到一個麻煩的東西。從自己找到的物品裡挑三件，分三回合把它打跑（✅）。

**圖是共用的「形」，內容綁遇到它的角色**（✅）：奇幻角色遇到怪物，工程師遇到難解的 Bug，業務遇到難搞客戶的怒罵。

### 不可違反的前提

- 背景與小工具不呼叫 LLM、不啟動 WebView。
- prompt 不含步數、縣市、真實地點。
- **沒有「輸」**，只有平手（✅）。不責備、不催促，可以一直不理它。
- 沒有等級、體力、耐久、數值養成、付費。稀有度不影響勝負。
- 物品**不會用掉、不會壞**。出場後休息 24 小時（§4.7），與「使用」互不影響（✅）。
- 對手不守箱子；勝負不影響物品數量、稀有度或機率。
- 不仿任何既有遊戲的角色、美術、介面或系統名稱。

## 2. 遇到對手（💡）

- 每打開 **3～5 個**箱子（隨機，打開成功才算）遇到一個。每天走 8,000 步約一天一個。
- 最多等一個，不過期。等著的時候**不累計**下一個。
- 已有名稱的物品（**含休息中的**）不到 **3 件**時不出現。計數停在門檻，等湊滿再出現。
- 出現當下，程式抽好並存檔：主角、形、三回合弱點。手牌等按下開始打才發；骰子到該回合才擲。
- 主角＝目前同行角色隨機一位，存 id 與名字快照。沒有同行角色就不出現。
- 主角之後離席或被刪除：已存好敵人文字就照打；還沒有就換成現在同行的另一位，都沒有就先留著。
- 畫面位置：不佔箱子的位置。站在路邊，有小標籤「○○遇到了什麼？」。點它才開始。
- 可按「先不管它」退回，**它留著**；另給「繞過它」讓它離開，不留任何紀錄。

## 3. 敵人內容（✅ 綁角色）

### 3.1 形與圖

第一批 **6 個形**，每個一張圖。之後只往尾端加，id 不重用。

| id | 圖 | 給 LLM 的說明 |
|---|---|---|
| `tangle` | 纏成一團的線 | 纏住、糾結、怎麼理都理不清的東西 |
| `spike` | 尖刺炸毛團 | 很兇、很吵、碰到就刺人的東西 |
| `slab` | 壓扁的石塊 | 很重、擋路、搬不動的東西 |
| `fog` | 有眼睛的霧 | 模糊、看不透、讓人分心的東西 |
| `pile` | 歪歪的一大疊 | 一直堆高、做不完的東西 |
| `bounce` | 亂跳的球 | 停不下來、到處跑、抓不住的東西 |

### 3.2 生成

- **每位角色呼叫 1 次**，一次寫好六個形的敵人並存起來，之後每場 0 次。
- **第一次點開該角色的對手才生成**。角色卡、世界觀會送給目前選用的 LLM，第一次要另外同意（物品的同意不沿用）。
- 角色卡改了不自動重寫；「換一批敵人」由使用者按，按前說明會呼叫一次 AI。生成成功才換掉舊的。
- 換批會馬上套用到還沒開打的對手；開打後的文字與圖鑑不變（各自存文字快照）。
- 用主模型，與物品揭曉相同：`minimal: true`、`isReminder: true`、`omitEmotionTag: true`。
- ⚠️ 六個敵人的文字比一般回覆長，`openai.ts` 以 `settings.llm.maxResponseTokens * 3` 為上限。使用者設得小會被截斷，所以要傳一份**只改高回覆上限的設定副本**（例如至少 2,000），不可寫回設定。其他供應商的上限實作時一併確認。
- 花費約等於一則較長的聊天回覆。

### 3.3 LLM 要寫什麼

每個形一段：

| 欄位 | 限制 | 用在哪 |
|---|---|---|
| 名稱 | 3～10 字，看得懂 | 標題、圖鑑 |
| 出場 | 主角說的話，白話一句，40 字內 | 開場 |
| 大獲全勝 | 敵人怎麼收場＋主角一句話，50 字內 | 結果 |
| 打跑了 | 同上 | 結果 |
| 平手 | 它為什麼自己溜走＋主角輕鬆一句話，50 字內 | 結果 |

給模型的條件：主角角色卡、世界觀、六個形的說明。**不給**：步數、地點、天氣、使用者人設、物品、其他角色卡。

內容限制：

- **敵人是麻煩本身，不是人**（✅）。用「難搞客戶的怒罵」，不用「難搞的客戶」。只能是怪物、東西、現象或麻煩；不可以是真人、使用者、其他角色。
- 從角色的**世界與職業日常**取材；要打怪合理的就打怪（✅）。看不出來就寫街上的小搗蛋。
- 不寫生病、死亡、失業、欠錢、分手、霸凌、自傷、血腥。
- 不說現實問題已解決，不替使用者下建議。
- 平手文字不准有「輸、敗、可惜、再努力、下次要」的責怪意思，要像一起坐下休息。
- 不提程式、介面、桌面、預設角色（角色的**職業題材**，如工程師的 Bug，可以）。
- 六個要彼此不同。繁體中文（台灣用語），少用逗號串句。

輸出格式固定：六段，每段 `形：id` 加五行 `名稱：` `出場：` `大勝：` `打跑：` `平手：`。解析**逐段**檢查，缺任一欄該段作廢；至少 4 段有效才存，缺的形用備用文字。整體不合格視為失敗。

### 3.4 失敗與備援

沒網路、沒金鑰、拒絕同意、逾時（90 秒，走 signal）、格式不符：**照樣能打**。

- 每個形內建一套通用文字，例如「打結的線團」。主角的話也用通用句。
- 備用文字不存成該角色的敵人，下次遇到會再試一次。**同一場不重試**，文字在開打時定案。
- 失敗時短訊息說「這次先用普通的對手」，不擋玩法。

## 4. 一場怎麼打

### 4.1 四種做法

| 做法 | 分類 |
|---|---|
| 引開 | 發光、聲響 |
| 打動 | 字圖、舊物 |
| 困住 | 容器、零件 |
| 嚇一跳 | 自然、謎物 |

### 4.2 流程

1. 主角說出場的話。三回合的弱點**一次全部攤開**，用圖示加文字「第 1 回合怕：引開」。LLM 文字只負責有趣，不影響判斷。
2. 按下開始打，才從能出場的物品發**五件**並存檔（不足五件就全發）。每件只能出一次。對手放幾天再打，期間恢復的物品也能用。
3. 一回合出一件：**做法對擲兩顆取高，不對擲一顆，4 以上贏這回合**。
4. 三回合結束看結果。每回合約 2～3 秒演出，可點一下跳過。

弱點：每回合從四種做法隨機抽，三回合不可全部相同。

手牌：從已有名稱、能出場的物品隨機抽（抽過籤語的也可以），盡量不重複同一品項。收藏裡有對應做法時，至少保證一件符合某回合，**不保證三回合都有**，取捨才存在。

骰子沿用 `core/random/dice.ts`：`{ tool: 'dice', faces: 6, count: 2, keepHighest: 1 }` 或 `count: 1`。這支直接用 `Math.random`，測試時模擬它。

### 4.3 其他角色幫打（✅）

- 出的物品由**找到它的角色**拿出來。是主角找到的就由主角出手；是其他同行角色，就由那位跳上場幫打。
- 沒贏的回合，如果出手的是同行角色（主角或幫手），可以**重擲一次，整場共一次**。要不要用由玩家決定，重擲後以新結果為準。
- 找到物品的角色現在不同行：主角代打，不能重擲。
- 幫手不用生成台詞，畫面寫「○○來幫忙」。

### 4.4 機率（精算）

「要不要重擲」取最有利的打法：

| 三回合做法 | 至少打跑 | 大獲全勝 | 至少打跑（有重擲） | 大獲全勝（有重擲） |
|---|---|---|---|---|
| 全對 | 84% | 42% | 95% | 74% |
| 對兩回合 | 75% | 28% | 91% | 56% |
| 對一回合 | 63% | 19% | 81% | 42% |
| 全不對 | 50% | 13% | 69% | 31% |

「有重擲」那兩欄各自以「至少打跑」「大獲全勝」為目標計算，且假設每回合都能重擲。是上限，不是承諾。

### 4.5 結果（✅）

| 贏幾回合 | 結果 | 圖鑑 |
|---|---|---|
| 3 | 大獲全勝 | 遇過＋打跑過＋大獲全勝 |
| 2 | 打跑了 | 遇過＋打跑過 |
| 0～1 | 平手，它溜走了 | 遇過 |

- 不顯示敗場、勝率、連勝。回合沒贏時寫「它閃過了」，不寫「失敗」。
- 平手不用紅色、打叉或失敗音效。
- 同一個敵人之後可再遇到。
- 結果頁：「聊聊這一場」「回到旅途」。

### 4.6 中斷與防重刷

- 手牌發好就不重發，重開也是同一手。
- **每擲先存檔再演出**；App 中途關掉，回來從同一回合繼續，不能靠重開重骰。
- 存檔要檢查回合編號，連點不會出兩件。
- 手牌中的物品若被丟掉，改用存檔時的名稱、分類、發現者快照繼續。
- 結束後一律寫紀錄，並清掉這個對手，重抽下一個門檻。

### 4.7 休息 24 小時（✅ 2026-11-25）

- **出過場**的物品，從那一回合起 24 小時後才能再出場。只發到手牌但沒出的不休息。重擲不重新計時。
- 時間存在物品自己身上：`WalkItem.lastBattleAt`（`items.json`，只存本機），實作戰鬥時才加欄位。
- 純函式判斷：沒有紀錄、滿 24 小時、或**上次出場在未來**（手機時間往回調）都算能出場。
- 開始打時能出場的不到 3 件，就讓**休息最久**（上次出場最早）的先回來，補到 3 件，不會卡住。補回來只進這一手，`lastBattleAt` 不清，出了場才更新。
- 開始時連同休息中的都不到 3 件（例如被丟掉），不開打，對手留著，畫面寫「再找幾件物品吧」。
- 回合存進 `battles.json` 後，再寫物品的 `lastBattleAt`；取回合存檔的時間，續打與結束時補寫一次，重做不會變。物品已被丟掉就略過。
- 冷卻不擋「使用」「聊聊」「丟掉」。「使用」也不影響冷卻。

| 位置 | 顯示 |
|---|---|
| 物品清單 | 小字「休息中」 |
| 物品卡 | 「休息中，還有 6 小時 21 分鐘可再出場」 |
| 物品卡，不到 1 小時 | 只寫分鐘 |
| 物品卡，不到 1 分鐘 | 「馬上就好」 |
| 時間到 | 消失 |

每分鐘更新。挑物品的畫面只發能出場的（含補回來的），不放休息中的灰格。

## 5. 聊聊這一場

- 按下才送進目前對話，約等於一則聊天。沒聊過角色不會主動提。
- 訊息是程式拼的：敵人名稱、誰遇到、每回合誰拿了什麼（物品名）、結果。不含骰面與步數。
- 物品名稱和敵人文字會進對話，因此跟著對話、摘要、S2 對話同步走。這點與「聊聊這個」相同。

## 6. 對手圖鑑

- 今日旅途多一個「對手」分頁，依角色分區。
- 一格＝一個角色的一個形，顯示共用圖、名稱、遇過／打跑過。沒遇過的顯示淡色剪影，不顯示總數壓力。

## 7. 資料

新檔 `modules/desktopst.walk/battles.json`（鍵加在 `walkKeys.ts`）。**只存本機，不進 S2、不進設定包**。備份功能做的時候比照物品。

```ts
interface BattleStore {
  consented: boolean
  opened: number          // 打開成功的箱子數
  nextAt: number          // 0＝還沒抽
  foes: Record<characterId, { name: string; madeAt: number; list: Record<FoeFormId, FoeText> }>
  current?: {
    id: string
    leadId: string; leadName: string
    form: FoeFormId
    weak: [Approach, Approach, Approach]
    hand?: { itemId: string; name: string; category: ItemCategory; finderId: string; finderName: string }[]  // 按下開始打才有
    text?: FoeText        // 開打時定案
    rounds: { at: number; itemId: string; rolls: number[]; kept: number; won: boolean; helperId?: string }[]
    rerollUsed: boolean
  }
  log: BattleRecord[]     // 最多 20 場
  dex: Record<`${characterId}:${FoeFormId}`, { met: number; won: boolean; perfect: boolean; text: FoeText; leadName: string }>
}
```

- 讀取時逐欄正規化，壞資料退回預設；未知形 id 略過。
- 寫入走 `updateCollection` 同型的排隊。物品檔只多寫 `lastBattleAt`，走既有 `updateCollection`（§4.7）。
- 計數放在揭曉**由無名變有名**的那一次：`walkItems.doReveal()` 成功處回呼，已揭曉再點不算。寫到一半中斷頂多少算一次，不補。
- 完成後推 `state-invalidated`。
- 清除陪伴同行資料**不清**這份；另設「清除對手紀錄」。

## 8. 介面與美術

- 美術由 Codex 畫平塗可愛風，圓潤、沒有尖角血腥、沒有文字。
- 第一批要 **6 張形（透明底、正面、靜態一張）** 與 **4 個做法圖示**。6 個形的輪廓要能一眼分開，配色不依賴紅綠。
- 動作用 CSS：出現時輕彈、被打中時晃一下、溜走時往路邊滑走。系統設定減少動態時只切換畫面。
- 角色用既有頭像與 `Companion`。不另畫戰鬥姿勢。
- 深色主題與 12 組配色都要能看。變數要先對 `theme.ts` 的 `ThemeVars`。
- 選單用語：分頁「對手」、動作「拿出來」、結果「大獲全勝／打跑了／平手，它溜走了」。不用「攻擊、傷害、血量、戰敗」。

## 10. 分步實作

1. **核心**：`src/core/walk/battle.ts` — 形、做法、出現、休息判斷、發牌、回合、重擲、結果、正規化。純函式，亂數注入。附備用文字。
2. **落地**：`src/mobile/runtime/walkBattle.ts` ＋ 鍵；物品加 `lastBattleAt`（含正規化）；揭曉成功計數的接點。
3. **可玩版**：路上的對手、過招畫面、結果頁、物品的「休息中」，先用備用文字和佔位圖。**先玩幾天**，確認好玩再往下。
4. **角色敵人**：prompt、解析、同意、生成、失敗備援、換一批。
5. **圖鑑與聊聊**：「對手」分頁、聊聊這一場、清除紀錄。
6. **美術**：換上 6 張形與 4 個圖示。

每一步都可單獨停。第 3 步結束的檢查題：取捨會不會太明顯、每天一個是否太多。若只是在對圖示，第一個要試的調整是**第三回合的弱點先蓋住**，第二回合後才翻開（現況是 owner 定案的全部攤開，改之前要問）。

## 11. 測試重點

**核心（純函式，注入亂數）**

- 門檻只在 3～5；等待中不累計；物品不足 3 件不出現，湊滿就出現。
- 弱點不會三回合相同；手牌不重複同一件，不足五件全發，抽過籤語的可進。
- 出現時沒有手牌；按下開始打才發並存檔，重開不重發，發牌後恢復的物品不補進這一手。
- 休息：差 1 毫秒滿 24 小時仍休息、剛滿就能出；上次出場在未來視為能出；沒出的手牌不休息；重擲不重新計時。
- 能出場的不到 3 件，依上次出場由早到晚補到 3 件；補回不清時間；同時間結果穩定。
- 剩餘時間文字：6 小時 21 分鐘、剛好 1 小時、不到 1 小時、不到 1 分鐘、時間到。
- 八類都對到做法，沒有遺漏。
- 做法對用兩顆取高、不對用一顆；3 以下不贏、4 以上贏。
- 贏 0、1 ＝平手，2 ＝打跑，3 ＝大勝。
- 重擲整場一次；已贏的回合、不同行的發現者不能重擲；重擲以新結果為準。
- 物品出過不能再出；**過招只改出過場物品的 `lastBattleAt`**，籤語與其他欄位不變、不刪。抽籤語不改 `lastBattleAt`。
