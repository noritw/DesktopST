# 新聞進 Prompt 的上下文補強（設計稿）

> 日期：2026-08-07｜狀態：**設計定案待實作**（owner 提出，尚未排程開工）
> 相關：`src/core/news/trigger.ts`、`docs/news-module-design.md`、`docs/news-reader-mobile-plan.md`
> 觸發原因：用新聞找角色聊天時，角色常只拿到標題（或 Google 新聞的「相關標題串」），容易斷章取義。

---

## 1. 問題

現行注入素材只有：

```
Title: …
Summary: …   ← RSS description；Google 新聞常是「同事件其他標題」用／串起，不是文章大意
```

見 `buildNewsContextString`／`buildNewsDirective`（`core/news/trigger.ts`）。
規格原本刻意只餵「標題＋摘要」、新聞報也不做全文閱讀（點原文開瀏覽器）。
但當 summary 資訊量不足時，角色只能腦補 → 斷章取義。

影響路徑：

| 路徑 | 現況 |
|---|---|
| 桌面／手機「聊這個」 | 把 `title\nsummary` 塞進輸入框 |
| 「說點什麼」／定時陪聊 | `getNewsInjectionForSpeak` → context + directive |
| 主題模式（釘住話題） | 同樣只有 title／summary |

---

## 2. 目標

在**不強迫角色照念全文**的前提下，讓 prompt 裡的事實足夠支撐「講得出發生什麼事」，
並讓使用者能**事前／事後核對、手動改正**餵給角色的那段上下文。

### 2.1 顯示與 Prompt 分離（owner 2026-08-07 定案）

| 層 | 內容 |
|---|---|
| **聊天記錄 UI** | 只顯示**新聞標題**（可點） |
| **送進 Prompt 的背景知識** | 標題 ＋ **全文節錄或輔助模型大意**（enrich 結果） |
| **點標題開啟的檢視／編輯面** | 顯示「即將／已經寫進 Prompt」的那段全文節錄／摘要，**可手動修改**後再送出或覆寫 |

重點：

- 使用者平常看對話不會被長文淹沒，只看到標題。
- 角色實際讀到的是 enrich 過的事實，不是單薄標題。
- 若不信任自動摘要，點標題進去改；改完的文字才是真正進 prompt 的版本。

非目標：

- 不做新聞報內的全文閱讀器（「開原文」仍開瀏覽器）
- 不改角色口吻優先原則（陪聊回覆仍走既有 `replyModel`；**摘要**走輔助模型）
- 不為了這件事重寫新聞模組

---

## 3. 建議方案（採 B：條件觸發）

### 3.1 決策流程

對即將注入的一則 `NewsItem`：

1. 評估現有 `summary` 是否「夠用」
2. 夠用 → 用現有 summary 當 prompt 上下文
3. 不夠用 → 嘗試抓原文 → 依長度決定「全文節錄」或「輔助模型摘要」
4. 任一失敗 → 退回現況，並在 debug／toast 記一筆（不擋聊天）
5. 產出可編輯的 `promptContext`（見 §3.5／§3.7），寫進 prompt；UI 只掛標題

### 3.2 「summary 夠用」的判定（初稿，實作時可調）

同時滿足才算夠用：

- `summary` 非空，且與 `title` 不實質相同
- 長度 ≥ **80** 字（可調）
- **不像** Google 新聞相關標題串：不含 `／` 分隔的多段短句，或 `／` 段數 ≤ 1

### 3.3 原文取得

- 對 `item.url` 發 HTTP GET（電腦端／`main` 執行；手機獨立模式之後再說）
- 抽正文：優先簡單可讀性抽取（title + main text），失敗則整頁純文字截斷
- 逾時建議 **8s**；失敗不重試超過 1 次
- 付費牆／空內容／非 HTML → 視為失敗，退回現況

### 3.4 長度門檻

| 正文長度（字元，去空白後） | 處理 |
|---|---|
| ≤ **1200** | 直接當 prompt 上下文（可再硬性上限 1200，避免爆 context） |
| > 1200 | 呼叫**輔助模型**濃縮成 2–4 句繁中事實摘要（約 120–280 字） |
| 抓失敗 | 維持原本 Title／RSS Summary |

摘要 prompt 約束（示意）：

- 只寫事實，不評論、不推測
- 繁體中文（台灣）
- 不要標題黨用語；不清楚就寫「細節不明」
- 輸出純文字（實作時固定一種格式）

### 3.5 資料怎麼掛

- **不永久改寫** RSS 的 `item.summary`（避免污染新聞報列表）
- 另存「這次聊天用的上下文」：
  - 建議掛在訊息的 `newsLink`（或等價欄位）上，例如：
    - `newsLink.title`：UI 顯示用
    - `newsLink.url`：開原文（瀏覽器）仍可用
    - `newsLink.promptContext`：**實際進 prompt 的那段**（節錄／摘要／使用者改過的版本）
  - enrich 當下也可先放執行期 cache（同 `newsId` 數小時），避免連點重抓
- `buildNewsContextString` 改吃 `promptContext`（有則用之，無則退回 title＋summary）

### 3.6 開關與成本

建議設定（新聞模組進階，預設開）：

- `enrichForChat: boolean`（預設 `true`）
- 關閉時行為＝今日現況（標題＋RSS summary 進 prompt；無獨立可編輯上下文）

Token：只有「summary 不夠用且成功抓到長文」才打輔助模型；短文直塞零 LLM 成本。

### 3.7 UI：標題連結 → 檢視／編輯 Prompt 上下文（owner 定案）

適用路徑：手動「聊這個」、以及主動陪聊產生的新聞泡泡／訊息。

**聊天記錄**

- 使用者訊息或新聞相關泡泡上，可見的是**標題**（短）。
- 標題可點 → 打開「新聞上下文」面板（sheet／小窗／lightbox 擇一，跟現有視覺語言一致即可）。

**面板內容**

- 標題（唯讀或可一併改，實作時定；預設唯讀標題、可編上下文）
- 多行文字區：目前的 `promptContext`（全文節錄或摘要）
- 說明一句：「這段會寫進角色看到的背景，不會整段出現在聊天泡泡裡。」
- 動作：
  - **儲存**：覆寫該則的 `promptContext`（若訊息已送出：只影響之後再組 prompt／主題模式延續時是否重讀——見下方「已送出」）
  - **重新整理／重抓**：可選；再跑一次 enrich，覆蓋未手動改過的版本（若已手動改過要確認）
  - **開原文**：仍開瀏覽器（與現況「開原文」相同）

**手動「聊這個」時序（建議）**

1. 使用者按「聊這個」→ 顯示「整理中…」（enrich）
2. enrich 完成 → **先打開上下文面板**（帶入自動結果），使用者可改
3. 確認後 → 輸入框／送出只帶**標題**當可見內容；`promptContext` 另存並在組 prompt 時注入
4. （備選）若嫌多一步：也可先塞標題進輸入框並附上可點的「檢視上下文」；但 owner 要的是能改再進 prompt，**確認後再送**較符合意圖

**主動陪聊（「說點什麼」／排程）**

- 角色發話前仍要 enrich（可延遲一點）
- 泡泡／訊息上的新聞標題可點，打開同一套面板看「當時餵進去的上下文」
- 若使用者事後改了 `promptContext`：對**已產生的那則回覆**不回溯改寫；對**後續主題模式／同一則新聞的延續**使用新版本（實作時在 `topicState` 同步 `promptContext`）

**已送出訊息**

- 面板仍可開來看「當初進 prompt 的內容」
- 允許編輯並存檔 → 供之後延續話題使用；不要偷偷重跑已完成的 LLM 回覆

## 4. 架構落點

| 層 | 職責 |
|---|---|
| `main/`（新小模組或 `modules/news/`） | fetch URL、抽正文、呼叫 utility、cache |
| `core/news/trigger.ts` | 組字串；吃 `promptContext` |
| 訊息／`newsLink` | 存 title（顯示）＋ `promptContext`（prompt） |
| 桌面／手機聊天 UI | 標題可點 → 共用的上下文檢視／編輯面板 |
| 桌面「聊這個」／手機 `chatAbout` | enrich →（可選確認）→ 寫入訊息欄位 |
| 手機獨立模式 | B3 之後再說（需自連外）；遙控模式走電腦端即可 |

⚠️ 業務規則（門檻、夠用判定）能純函式化的放 `core/`，I/O 留平台層。

---

## 5. 風險

| 風險 | 處理 |
|---|---|
| 網站反爬／付費牆 | 失敗退回；不要為單一媒體特製 |
| 延遲（「說點什麼」變慢） | 逾時短；陪聊必須等素材；手動「聊這個」顯示「整理中…」 |
| 輔助模型幻覺 | prompt 強調「只根據內文」；**加上可編輯面板**讓使用者校正 |
| 使用者改完與角色已回覆不一致 | 不回溯舊回覆；只影響後續 |
| 法律／ToS | 只在使用者主動聊／系統陪聊該則時抓；`promptContext` 可隨對話存，不另建全文索引庫 |

---

## 6. 驗收（實作時）

1. Google 新聞關鍵字來源、summary 為標題串：enrich 後角色能講出事件大意
2. 聊天記錄裡使用者／泡泡側只看到**標題**，看不到整段摘要正文
3. 點標題可打開面板，內容＝寫進 prompt 的節錄／摘要；可改、存檔
4. 改過後再延續同一則新聞話題時，角色吃到的是改過的版本
5. 短篇全文：prompt 內接近原文、無 utility call；長文才打輔助模型
6. 抓取失敗：聊天仍可用；面板可顯示退回的 RSS summary 或「僅標題」
7. `enrichForChat: false`：與今日 bit-identical（無獨立面板也可接受）

---

## 7. 建議排程

不擋 B3 階段 7（APK）。建議獨立小功能：桌面先做 enrich ＋標題連結編輯，手機遙控版跟同一套 `newsLink`／面板契約。
